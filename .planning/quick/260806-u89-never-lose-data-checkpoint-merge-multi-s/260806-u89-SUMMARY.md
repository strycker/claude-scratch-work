# Quick Task 260806-u89: Never-Lose-Data Checkpoint Merge + Multi-Source Fallbacks + Offline Snapshots Summary

**Merge-on-save checkpoints that refuse empty overwrites, a config-driven splice fallback chain wiring gold to IAU, and an offline snapshot export/restore CLI for the platform data layer.**

## Performance

- **Duration:** ~55 min
- **Tasks:** 3/3 completed
- **Files modified/created:** 17 (11 modified, 6 created)
- **Commits:** 3 (one per task, plus this docs commit handled by the orchestrator)

## Accomplishments

- `CheckpointManager.save()` now merges `daily_raw`/`monthly_raw`/`macro_raw`/`asset_prices` with whatever is already on disk instead of unconditionally replacing it, and refuses outright to overwrite a non-empty checkpoint with an empty frame — closing the exact bug that produced this repo's committed 0×0 `daily_raw`. Derived frames (`monthly_features`, `features*`) are explicitly excluded and still replace wholesale.
- Generalized the one-off oil `fallback_col` into an ordered candidate chain any splice class/source-column key can declare in `config/platform_settings.yaml`. `gold`'s `source_col` is now `[gold_spot, IAU]` — falls back to IAU's own price when macrotrends is unreachable, with the IAU-is-not-spot-gold caveat documented in three places (module docstring, config comment, `docs/splicing_rules.md`).
- `build_monthly_spine` now feeds the splice engine `concat(macro, monthly_prices)` instead of `macro` alone — without this the gold→IAU chain could never resolve, since IAU only exists in the monthly ticker frame.
- Every splice class's resolution is logged at INFO on every run and recorded in `.attrs["splice_provenance"]`, persisted via `write_splice_provenance()` next to the platform checkpoints.
- New `trading_crab_lib.platform.snapshots` module + `scripts/platform_snapshot.py` CLI (`export`/`restore`/`list`) for offline dev snapshots of the platform checkpoint namespace, opt-in via `TC_USE_SNAPSHOTS`, with a persistent `"source": "offline-snapshot"` meta marker so a restored snapshot can never be silently mistaken for live data.
- Fixed a real test-isolation gap: `PLATFORM_CHECKPOINT_DIR` bypassed the `TC_CHECKPOINT_DIR` env override entirely (it's a module constant, not env-driven), so platform tests were writing to the real `data/checkpoints/platform/` directory. `tests/conftest.py`'s session fixture now redirects it too.

## Decisions Made

See `key-decisions` in frontmatter. The single most consequential one: `build_monthly_spine`'s splice input changed from `macro`-only to `concat(macro, monthly_prices)`, guarded only for the both-empty case rather than "skip splice whenever macro alone is empty." This is a deliberate, plan-directed behavior change (not a bug) — it's exactly what makes the gold→IAU chain reachable, and it is consistent with this task's overall "fail loud on missing data, never silently skip" theme. If a future macro-fetch-only failure (with prices succeeding) needs to skip splice quietly instead of raising, that would be a new, separate decision.
