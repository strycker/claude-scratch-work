<objective>
Make the platform data layer un-loseable, source-agnostic, and workable offline.

Three independent deliverables, ordered by how much data they protect:

1. **Never-lose-coverage checkpoint writes.** `build_monthly_spine` currently calls
   `cm.save(daily, "daily_raw")` unconditionally. When every price source failed it wrote
   a 0x0 frame straight over a good one. The evidence is committed in this repo right now:
   `data/checkpoints/platform/daily_raw.meta.json` reads `"rows": 0, "columns": 0`, and
   `monthly_raw.parquet` has 15 columns with no ticker among them. Task 1 makes a degraded
   source physically unable to do that again.
2. **Multi-source fallback chains in the splice config.** Generalize the one-off
   `fallback_col` that only `oil` uses into an ordered candidate chain that any splice class
   and any source-column key can declare, then wire `gold` to `IAU`. Config-driven; zero
   ticker names in Python.
3. **Offline snapshots committed to the repo.** An export/restore CLI plus a committed,
   provenance-stamped snapshot location so development continues when every source is blocked.

Purpose: hobbyist models die of single-source dependency and of overwriting the data they
already had. Both failure modes have already fired in this repo. This plan closes both and
adds the offline escape hatch.

Output: merge-on-save semantics in `checkpoints.py`, a config-driven source-resolution layer
in `splice.py`, a new `platform/snapshots.py` + `scripts/platform_snapshot.py`, a committed
`data/snapshots/platform/` location, two docs, and three test suites.

Note on task shape: GSD defaults to a leading tracer slice with expansion tasks built on it.
The three deliverables here are genuinely independent features, not one slice plus expansions,
and the task count/order is fixed by the request. Task 1 is nonetheless first because it is
the one that protects data the user is about to put at risk.
</objective>

  <behavior>
Pure merge function `merge_preserving(existing, new) -> (merged, stats)`:
  - union of columns and of index; index sorted ascending
  - overlapping cell: take `new` where it is non-NaN, else keep `existing`
  - column present only in `existing`: kept intact
  - column present only in `new`: added
  - column order deterministic: `new`'s order first, then existing-only columns
  - `stats` reports cols_kept_from_disk, cols_added, cols_updated, rows_kept_from_disk,
    rows_added, cells_filled_from_disk
  - duplicate column labels in either frame: return `new` unchanged with a
    `degraded` flag in stats (combine semantics are undefined under duplicate labels)

`CheckpointManager.save` behavior, per required-coverage list:
  - Test A: `save(non_empty,"daily_raw")` then `save(pd.DataFrame(),"daily_raw")` ->
    on-disk parquet bytes and meta `rows`/`columns` are unchanged, and a WARNING is emitted.
  - Test B: stored has columns {SPY,IAU,TLT}; new has {SPY,TLT} -> reloaded frame still has
    an IAU column with its original values.
