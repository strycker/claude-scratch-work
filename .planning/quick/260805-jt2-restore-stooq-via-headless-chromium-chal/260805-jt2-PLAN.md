being impersonated at the TLS layer.

Public API — exactly two functions:

`playwright_available() -> bool` returns `_PLAYWRIGHT_AVAILABLE`.

`fetch_stooq_csvs(urls: dict[str, str], *, warmup_url: str = _STOOQ_WARMUP_URL,

Control flow:
1. If `urls` is empty, return `{}` immediately without launching anything.
2. If not `_PLAYWRIGHT_AVAILABLE`, log a WARNING that names the two commands the operator
   must run (`pip install 'playwright>=1.40'` then `playwright install chromium`) and

   process-spawning calls and requires zero hits).
3. Open `with sync_playwright() as pw:`. Build `launch_kwargs = {"headless": True}` and add
   `executable_path` ONLY when `os.environ.get(_CHROMIUM_PATH_ENV)` is set and non-empty —
   when unset the key must be absent entirely, not present-and-None, so Playwright's own
   browser resolution applies. Rationale to state in a comment: an ambient Chromium build
   can mismatch the installed playwright package, and this env var is the operator's escape
   hatch.
4. `browser = pw.chromium.launch(**launch_kwargs)`, then `try:` ... `finally:
   browser.close()`. The close must survive a mid-batch failure — this is the only reason
   the try/finally exists, so do not collapse it.
5. Inside: `context = browser.new_context()`, `page = context.new_page()`,

6. Loop `for i, (ticker, url) in enumerate(urls.items())`: sleep `rate_limit_seconds` when

   browser's TLS fingerprint and identity, which would reintroduce exactly the mismatch
   this codebase just removed. In the sync API `resp.ok` is a property and `resp.text()` is

7. Wrap each per-ticker fetch in its own try/except so one failing ticker does not abort
   the batch; log a WARNING and continue.
8. Wrap the whole launch/navigate block in a broad `except Exception` carrying

   NEVER raise through to its caller under any condition.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stooq.com -> headless Chromium | Untrusted remote JavaScript is fetched AND EXECUTED locally — a materially wider boundary than an HTTP GET, and the point of this change |
| stooq.com -> `_parse_stooq_csv` | Untrusted response body crosses into pandas parsing and then into price data |
| operator environment -> `TC_CHROMIUM_PATH` | An env var selects which binary is launched as a browser |
| PyPI -> `[browser]` extra | A new third-party dependency is declared in library packaging |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-jt2-01 | Tampering | `_parse_stooq_csv` in prices_daily.py | high | mitigate | Single non-duplicated `startswith("date,")` guard rejects any body that is not a CSV before pandas sees it; gated by `grep -c ... == 1` and by a test asserting a challenge page returned via the BROWSER path is rejected identically to one on the HTTP path |
| T-jt2-02 | Elevation of Privilege | `browser.fetch_stooq_csvs` executing remote JS | medium | mitigate | Headless launch, a fresh `new_context()` per run with no persistent profile and no stored credentials, navigation limited to the single configured warm-up URL, and `browser.close()` in a `finally` so no orphan browser process survives a mid-batch failure |
| T-jt2-03 | Spoofing | `TC_CHROMIUM_PATH` binary selection | low | accept | The env var is operator-controlled and carries exactly the trust level of the interpreter already running the pipeline; it exists because ambient Chromium builds mismatch the installed playwright package. Documented, not validated |
| T-jt2-04 | Denial of Service | per-ticker request loop against Stooq | low | mitigate | One browser launch per run (not per ticker) and `_BROWSER_RATE_LIMIT_SECONDS` pacing consistent with the existing `_STOOQ_RATE_LIMIT_SECONDS`; asserted by a sleep-call-count test |
