Helper `_redact(text: str, api_key: str | None) -> str`. Returns *text* with every occurrence
of *api_key* replaced by a fixed mask string; returns *text* unchanged when *api_key* is falsy.
This is the single mechanism keeping the credential out of logs — EVERY string derived from an
exception or a response body that reaches a log call must be routed through it. Comment that
the transport library can echo request detail into an exception message, which is precisely why
scrubbing is centralized here rather than relied upon per-call-site.

Helper `resolve_api_key(cfg: dict[str, Any] | None = None, api_key: str | None = None) -> str | None`.
Precedence: explicit *api_key* argument, then the `_API_KEY_ENV` environment variable, then
`cfg.get("tiingo", {}).get("api_key")`. Whitespace-only values are treated as unset. Returns
None when nothing is configured. Never logs the resolved value.

Helper `_parse_rows(ticker: str, rows: list[dict[str, Any]]) -> pd.Series | None`. Walks the
JSON list. For each row take the date key and prefer the adjusted-close key; only when that key
is absent or None fall back to the unadjusted close key, and on the FIRST such fallback for a
ticker emit one DEBUG record naming the ticker (one per ticker, not one per row). Rationale to
state in a comment: the adjusted series matches the `auto_adjust=True` semantics the yfinance
path already produces, which is what keeps the two sources interchangeable downstream. Skip
rows missing both. Build the index with `pd.to_datetime(dates, utc=True)` then `.tz_localize(None)`
then `.normalize()` — tz-naive, daily, NO resampling (D-05: daily is what gets persisted).
Sort the index, drop duplicate index entries keeping the last, set `.name` to the ticker,
`.dropna()`. Return None (never an empty Series) when nothing parsed, so callers have one
falsy check.

Helper `_fetch_one(ticker, start, end, api_key, session, base_url) -> pd.Series | None`.
Builds `f"{base_url}/{ticker}/prices"` with `startDate` and `endDate` supplied as query
parameters. The credential is NOT among them — it is supplied ONLY as an `Authorization`
header whose value is the word `Token`, a space, then the key. State in a comment that a
credential embedded in a URL leaks into logs, proxy access logs and exception messages, which
is why it lives in a header. Loop up to `_MAX_RETRIES`: call `http_get(url, session=session,
headers=..., timeout=30)` inside `try/except HTTP_ERRORS as exc:  # noqa: BLE001` — on
exception log a WARNING naming the ticker and `_redact(str(exc), api_key)`, then break out and
return None. Read `resp.status_code`; when it equals `_RATE_LIMITED_STATUS`, log a WARNING
naming the ticker, the status code and the attempt number, sleep
`_BACKOFF_BASE_SECONDS * (2 ** attempt)`, and continue to the next attempt. Any other non-200
status logs one WARNING naming the ticker and the status code and returns None with no retry.
On 200, call `resp.json()` inside `try/except (ValueError, TypeError) as exc` logging a WARNING
with `_redact(str(exc), api_key)` and returning None; otherwise delegate to `_parse_rows`.
After the loop is exhausted, log a WARNING that the retry budget for that ticker is spent and
return None. Log ticker symbols, status codes and attempt numbers — never a header dict, never
a response body, never the credential.
