# Quick Task 260805-570: Fix Stooq/macrotrends bot-blocking, ALFRED schema bug, silent build-OK, yfinance rate-limit discard

One-liner: shared curl_cffi browser-impersonation client wired into Stooq/macrotrends, ALFRED's required-column contract narrowed to match fredapi's real 3-column response, build_platform_data.py now asserts real row/column counts instead of a column-name substring heuristic, and yfinance daily fetch chunks + retries with backoff instead of discarding everything on one rate-limited call.

## What Was Built

**Task 1 — `src/trading_crab_lib/ingestion/http.py` (new) + Stooq/macrotrends rewire**
`browser_session()` builds a `curl_cffi.requests.Session(impersonate="chrome", verify=True)`
when curl_cffi is installed, falling back to a plain `requests.Session` with browser
headers, or `None` (with a WARNING) if neither client is importable. `http_get()` reuses a
supplied session or builds a one-shot one. `HTTP_ERRORS` is a client-agnostic exception
tuple built from whichever transport(s) imported (always includes `OSError`, which both
clients' `RequestException` subclass). The module contains no import from
`ingestion/assets.py` (verified by test and by the plan's ast/grep-style gate).

`_batch_stooq_daily` now builds one session before its ticker loop, calls `http_get`
instead of `requests.get`, and sleeps 1.5s between tickers (skip before the first). The
existing non-CSV challenge-page guard (the check that a response must start with the
`Date,` CSV header before being parsed) is untouched byte-for-byte.

`macrotrends._scrape_series` gained a `session` parameter and calls `http_get` instead of
`requests.get`; `fetch_all` builds one session before its series loop. The HTML-table
fallback path and the graceful-degrade-on-exception path are unchanged.

**Task 2 — `alfred._detect_vintage_columns` schema fix**
`_REQUIRED_VINTAGE_ROLES` narrowed from 4 roles to 3 (`realtime_start`, `date`, `value`);
`realtime_end` moved to a new `_OPTIONAL_VINTAGE_ROLES` tuple and is mapped only when
present. fredapi's real `get_series_all_releases()` response has exactly 3 columns —
`realtime_end` is commented out in fredapi's own source — so every previous ALFRED fetch
raised `ValueError` before this fix, 0/5 series, on every run. The test that previously
asserted the real 3-column shape *must* raise (the bug, codified as a passing test) was
rewritten to target a genuinely required role (`value` missing) instead.

**Task 3 — build guard + chunked yfinance**
`scripts/build_platform_data.py` gained a pure `check_price_coverage(df) -> str | None`
helper and `main()` now loads the actual `daily_raw` checkpoint (via the platform
checkpoint manager, catching `FileNotFoundError`) and asserts it via that helper — same
check applied to `monthly_features`. The deleted heuristic scanned column names for
substrings like `"tr"` (matches almost any column) and `"equit"` (matches
`equities_tr`, a multpl-derived column unrelated to price ingestion), which is exactly
why the script printed `BUILD OK` over a 0-row/0-column `daily_raw`.

`prices_daily._batch_yfinance_daily` now splits the ticker universe into chunks of 5
(`_YF_CHUNK_SIZE`), retrying each chunk up to 3 times with `2.0 * 2**attempt` second
backoff on a transport/rate-limit error or an empty result. A chunk that exhausts its
retries is skipped (logged) without discarding results already recovered from other
chunks. The MultiIndex/flat-column parsing logic was extracted verbatim into
`_extract_close_series()`.
