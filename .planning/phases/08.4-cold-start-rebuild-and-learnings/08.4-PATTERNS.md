## Pattern Assignments

### Module conventions (apply to every new file)

- Module docstring first, then `from __future__ import annotations`, then imports, then `log = logging.getLogger(__name__)`. This is the order in `serving.py`. Section dividers are `# ── Name ──`, exactly.
- Type hints on all public functions, `X | None` rather than `Optional`, and `pathlib.Path` throughout.
- The library uses no `print()`. In `state/__main__.py` only, use `print(...)  # noqa: T201` (precedent: `macro_daily.py:185`).
- Subprocess calls use list form with an explicit `cwd=repo_root`. Never use `shell=True`.
- Pass `--` before paths in git calls.

### `platform/state/archive.py` (manifest, create, list, reset)

**Analog for the git and registry facts:** `src/trading_crab_lib/platform/honesty/registry.py:53-62`

```python
def _git_sha() -> str:
    try:
        result = subprocess.run(["git", "rev-parse", "HEAD"], capture_output=True, text=True, check=True)
        return result.stdout.strip()
    except (subprocess.CalledProcessError, FileNotFoundError) as exc:
        log.warning("Could not determine git SHA for registry row: %s", exc)
        return "unknown"
```

Differences to apply:
- Pass `cwd=repo_root`. Existing helpers omit it, and the real repo must never be touched in tests.
- Get the trial count with `total_trial_count(paths.registry_path)` from `honesty/registry.py`. Do not re-implement the header-aware count. The ledger sha256 is `hashlib.sha256(path.read_bytes())`, or `null` when the ledger is absent.
- Hash `platform_settings.yaml` with sha256. Do not reuse the checkpoint `config_hash`, which is the MD5 of the legacy `settings.yaml`.
- **Deterministic tar** (D-T10 and RESEARCH Q10; there is no in-repo analog):
  - build with `gzip.GzipFile(filename="", mode="wb", fileobj=raw, mtime=0, compresslevel=9)` wrapping `tarfile.open(fileobj=gz, mode="w", format=tarfile.PAX_FORMAT)`;
  - sort members; set `mtime=0`, `uid=gid=0`, empty `uname`/`gname`, `mode=0o644`.
- Hash in 1 MiB chunks. `hashlib.file_digest` is 3.11+ and CI runs 3.10.
- **Atomic write:** build in `archives_dir/.tmp-<name>-<pid>/`, write `state.tar.gz` and then `manifest.json` last, re-open the tar and check its members against the manifest, then `os.replace` to `archives/<name>`. Refuse an existing name, and clean up in `try/finally`. `list` skips dot-directories.
- Manifest JSON is written `indent=2` with a trailing newline (pre-commit text hooks).
- Manifest fields:
  - per-file path, size and sha256;
  - archive sha256, code commit and dirty flag, config sha256;
  - trial count and ledger sha256;
  - `monthly_raw` first and last index (from the checkpoint `.meta.json` `index_start`/`index_end`);
  - UTC and CDT times, using `zoneinfo.ZoneInfo("America/Chicago")`;
  - `note`;
  - `build_provenance` (the embedded `build_provenance.json`, when present);
  - `serving` block (C4): `{"had_serving_state": bool, "class_prior": {...}}`, read from the `nowcaster_class_prior` parquet and never from a pickle;
  - `excluded` list (pickle paths only).
- `reset` flow: write `auto-<UTC yyyymmddThhmmssZ>`, then empty both trees, then print the restore hint. It needs `--yes` or an interactive `input()` confirm that names the emptied trees and the archive name. It never touches `registry/`. Keep `.gitkeep`.

### `platform/state/restore.py`

**Analog:** `src/trading_crab_lib/platform/report/serving.py:105-235` (`build_serving_artifacts(cfg, *, cm=None, output_dir=None)`). The command constant is `SERVING_BUILD_COMMAND = "python -m trading_crab_lib.platform.report.serving"` (l.84).

Conventions to replicate:
- Call `build_serving_artifacts(cfg, cm=CheckpointManager(paths.platform_ckpt), output_dir=...)` **in-process, with a lazy import inside the function**, because sklearn is heavy. Print `SERVING_BUILD_COMMAND` as the manual equivalent. `report/` must never import `platform.state`; add a test for that.
- The refit never writes the registry (`path=NO_REGISTRY` is hard-coded in serving).
- Order of operations:

  2. validate tar members: regular files only, relative POSIX paths, no `..`, no links, first segment allowed, size sum within the manifest sum;

  4. move into place.
- Refuse unless both trees are empty, and suggest `reset`.
- A commit or config-hash mismatch against HEAD is a warning (`log.warning`), not an error. A registry count lower than the ledger's, or higher, is also a warning.
- Refit only when `manifest["serving"]["had_serving_state"]` is true. Load the archived `asset_returns` and `returns_by_regime` BEFORE the refit overwrites them.
- Verify the refit prior against `manifest["serving"]["class_prior"]` at rel 1e-9, abs 0 (DECISIONS H-10), using `numpy.isclose(..., rtol=1e-9, atol=0)`. On failure exit non-zero with "refit does not reproduce the archive" and delete nothing.
- If there is nothing to refit, say so and leave the page in `no_regime` mode.
- A restore from a promoted archive gives a cold weekly state (the A-15 note is expected). `restore <name>` prefers `archives/<name>/`, and `--promoted` selects `archives/promoted/<name>/`.

### `platform/state/promote.py`

**Analog:** the `_git_sha` pattern above, extended with list-form subprocess calls.

Conventions to replicate:
- Rebuild a NEW deterministic tar from the local archive, skipping:
  - live-state basenames;
  - all pickles;
  - the `platform_notebook/` scratch subtree.
- Write it to `archives/promoted/<name>/` with a new manifest carrying `promoted_from`, `excluded` and the carried `serving` block.
- Size guard: default 50 MB, configurable, and `--force` warns and overrides.
- Dirty-tree check: `git status --porcelain --untracked-files=no`, drop paths starting with `archives/`, and refuse if any remain, naming them. There is no override flag.
- Git steps, all with `cwd=repo_root`:
  - `git add -- archives/promoted/<name>`;
  - `git commit -m ... -- archives/promoted/<name>`;
  - `git tag -a model/<name> -m <summary>`.
- Print `git push origin model/<name>` and never push. Do not use `--no-verify`.
- Do not claim the Claude attribution lines in the tool's commit message.
- `.gitignore` additions: `archives/*` and `!archives/promoted/`.
- `.pre-commit-config.yaml`: add `exclude: "^archives/promoted/"` to the `check-added-large-files` hook (`--maxkb=500`).
- Test with a throwaway repo in `tmp_path`:
  - run `git init` plus an initial commit;
  - isolate the environment with `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`;
  - pass `-c user.name=t -c user.email=t@t -c commit.gpgsign=false -c tag.gpgsign=false` on every call (this sandbox has `commit.gpgsign=true`);
  - the code takes `repo_root`, so the real repo is never touched.

## Shared Patterns

### Logging and errors
**Source:** `report/serving.py` (`log = logging.getLogger(__name__)`; `logging.basicConfig(level=logging.INFO)` in `main` only).
- Warn for flagged-but-allowed conditions.
- Raise specific exceptions for refusals, with actionable messages naming the path and the next command.
- Catch broad `Exception` only around network calls, marked `# noqa: BLE001`.
- Define `SourceFetchError(RuntimeError)` and a `StateError`.

### Atomic and pre-write validation
**Source:** `transforms_monthly.py` `_assert_lag_marker_allows_merge(cm, cfg)  # before ANY write`. Validate first, then write, so a refusal changes nothing.

### G-11 live-state exclusion
**Source:** `.gitignore:38,43-51`, `LIVE_STATE_BASENAMES`. Applies to promote only. Local archives keep live state, and reset empties everything under both trees.
