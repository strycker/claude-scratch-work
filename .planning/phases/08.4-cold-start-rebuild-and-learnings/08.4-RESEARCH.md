  - an archive over a size guard (default 50 MB, configurable; `--force` overrides with a warning);
  - a dirty working tree outside `archives/`.

**D-T4: `reset`: always auto-archive, never the registry**
- **Steps:** `reset` first writes `archive auto-<UTC timestamp>` (local, unpromoted), then empties the platform's `data/` and `outputs/` namespaces. It prints the archive name to restore from.
- **It never touches `registry/`.** A registry epoch stays a separate, deliberate action with its own ADR (8.5).
- **Confirmation:** needs `--yes`, or an interactive confirm. The confirm states what will be emptied and the auto-archive name.

**D-T5: `restore <name>`: no pickles; refit and verify**
- **Precondition:** restores into **empty** namespaces only. If they are not empty, it refuses and suggests `reset`, which auto-archives.
- **Checks before extracting:**
  - every file's sha256 is verified against the manifest;
  - a code-commit or config-hash mismatch against HEAD is printed as a **warning**, not an error. Restoring an old archive under new code is allowed but flagged.
- **Pickles are never archived** (P27). After extracting, `restore` runs the existing serving refit command (`SERVING_BUILD_COMMAND` in `report/serving.py`) only when the archive held serving outputs, then verifies the refit against the manifest. The verification method is Claude's discretion, e.g. served posteriors on the archived data equal the archived belief at rel 1e-9, or a documented equivalent.
- A restore that cannot refit, for example because no serving state was archived, says so and leaves the page to run in no_regime mode.

**D-T6: Fail-loud build from empty (DECISIONS D-08)**
- From an empty `data/`, `scripts/build_platform_data.py` (one command) builds raw → splice → features → holdout carve.
- **Merge-on-save fills raw source columns only**, never derived or spliced ones.
- **A single-source splice resolving to a fallback candidate fails the build**, unless the config explicitly allows that fallback for that class.
- **Any failed source fetch fails the build**, naming the source and how to retry.
- **The closing hint no longer invites a backtest re-run**, because that rewrites evaluation outputs.
- The build writes a provenance manifest beside the data: per source, fetch time, rows, date range and resolved splice candidate. It is reused by D-T2.

**D-T7: The no_regime weekly path needs no regime model**

## Summary

**The phase is mostly new code in a small `platform/state/` package (stdlib only), plus two surgical hardening changes to existing code.** The state tooling needs no third-party package: `tarfile`, `gzip`, `hashlib`, `json`, `subprocess`, `shutil`, `zoneinfo`, `argparse`. Everything the platform writes already lives under five allowlistable subtrees, and every path is a module-level constant evaluated at import time, so tests must inject paths explicitly (a `StatePaths` dataclass) rather than rely on `TC_*` env vars, and the repo's session-scoped `conftest.py` already monkeypatches two of those constants.

**Three findings change the shape of the plans.** (1) The legacy-import ratchet in `tests/unit/test_platform_legacy_import_ratchet.py` is pinned at exactly **31** and the tree has exactly 31 sites today, so a new `from trading_crab_lib import DATA_DIR` anywhere under `platform/` turns CI red. The fix is to extend the import line that `platform/checkpoints.py` already has (no new site). (2) `weekly.py::_build_report_inputs` is not "mostly optional" in `no_regime` mode: it hard-requires the nowcaster pickle, its class prior, `regime_labels`, `returns_by_regime` and `asset_returns`, and it advances and saves the regime belief and hysteresis state. D-T7 therefore needs a real model-free branch, not a wording tweak. (3) D-T6's "any failed fetch fails the build" collides with an existing ruling (A1: a failed `fred_daily` fetch warns and keeps exit 0, pinned by a test) and with ~10 existing synthetic `build_monthly_spine` tests; both are resolved below with a config switch following the repo's own `allocation_mode` precedent.

**Primary recommendation:** Build `platform/state/` (paths, archive+manifest, restore, promote, `__main__`) on stdlib with an allowlist scope and injected `StatePaths`; harden the build with (a) a `replace_columns` option on `merge_preserving`/`CheckpointManager.save` fed by the lag table's `derived` entries, (b) a pure splice-fallback gate and a pure source-coverage gate, both raising before any write and both enabled by a `build.fail_loud: true` key in the live config (absent key = legacy behaviour, pinned by a test), and (c) a model-free branch in `_build_report_inputs` that only engages when the model artifacts are absent.

### Q2. Merge-on-save (D-T6)

[VERIFIED: `src/trading_crab_lib/checkpoints.py` read in full]

### Q10. Tar safety, determinism, atomicity and git mechanics

**Extraction safety** [CITED: docs.python.org/3/library/tarfile.html]: extraction filters were added in 3.12 and "may be backported … use `hasattr(tarfile, 'data_filter')` rather than checking the Python version"; the `data` filter refuses absolute paths, paths escaping the destination, links to absolute or outside targets, and device files; 3.14 makes `data` the default. **Verified here:** `hasattr(tarfile, "data_filter")` is `True` on 3.10.20, 3.11.15, 3.12.3, 3.13.12. Older 3.10/3.11 patch levels lack it [ASSUMED: 3.10.0–3.10.11 and 3.11.0–3.11.3]. **Recommendation:** never rely on the filter alone. Because the tool writes every archive itself, validate members before extracting: only regular files, normalised relative POSIX names, first segment in the allowed arcname prefixes, no `..`, no absolute path, no symlink/hardlink/device, and `sum(sizes)` ≤ manifest sum (decompression-bomb guard). Then extract with `filter="data"` when `hasattr(tarfile, "data_filter")`, else plain extraction of the validated list. Extract into a staging dir, verify, then move.

**Deterministic archive** [VERIFIED: ran the same writer on 3.10/3.11/3.12/3.13 in the scratchpad]: sorted members; `TarInfo` with `mtime=0`, `uid=gid=0`, `uname=gname=""`, `mode=0o644`; `format=tarfile.PAX_FORMAT`; and the gzip layer built by hand, `gzip.GzipFile(filename="", mode="wb", fileobj=raw, mtime=0, compresslevel=9)`, with `tarfile.open(fileobj=gz, mode="w")` inside it. Result: sha256 `87b97798afdbd106…` on all four interpreters for both a fresh write and a rewrite after touching the source (mtime changed). The naive `tarfile.open(path, "w:gz")` gave two different hashes for identical content 1.1 s apart. Caveat [ASSUMED]: compressed bytes can differ across zlib builds (Linux vs macOS), so the archive sha256 is reproducible on one machine; the per-file sha256 list is the portable integrity record. Side effect: extracted files carry mtime 1970-01-01. Nothing in the platform reads file mtime (`is_fresh` uses meta `created`), so accept it.

**Atomic writes:** build everything in `archives_dir/.tmp-<name>-<pid>/` (same filesystem), write `state.tar.gz` then `manifest.json` last, re-open the tar and check its member list equals the manifest, then `os.replace` the directory to `archives/<name>` after checking the name is free; `try/finally` removes the temp dir on any failure. `list` skips dot-directories. `restore` stages next to the archives dir and falls back to `shutil.move` when the destination is on another volume.

**`promote`: use a tracked `archives/promoted/<name>/` subtree, not `git add -f`.** [VERIFIED: ran in a throwaway `git init` repo]: with `.gitignore` lines `archives/*` and `!archives/promoted/`, a file under `archives/local1/` is ignored (`check-ignore` reports `.gitignore:1:archives/*`) while `git add archives/promoted/p1` works with no `-f`, `git commit -m … -- archives/promoted/p1` commits only that path, and `git tag -a model/p1 -m "summary line" HEAD` works (a tag name with a slash is valid). Why the subtree: the promoted archive must be **rebuilt without** the G-11 files (C4), so it is a different artifact from the immutable local one; force-adding the local directory would commit live book state. Promote therefore (1) validates the source archive, (2) streams its tar into a new deterministic tar skipping live-state members (match by **basename**: `allocation_mode.*`, `asset_returns.*`, `executed_weights.*`, `hysteresis_state.*`, `nowcaster_class_prior.*`, `regime_belief.*`, `returns_by_regime.*`, `weekly_report.md`, in any directory, which also catches the notebook-scratch copies), pickles, and the `platform_notebook/` scratch subtree (scratch is not a model), (3) writes a new manifest with `promoted_from`, the `excluded` list and the carried-over `serving` block, (4) size-guards (default 50 MB, `--force` warns), (5) checks the tree, (6) `git add`, `commit`, `tag -a`, (7) prints `git push origin model/<name>` and does not push. `restore <name>` prefers `archives/<name>/` and accepts `--promoted` for the tracked copy. Retrieval on another checkout: `git checkout model/<name> -- archives/promoted/<name>`. Reserve the name `promoted` in the name check.

- **Dirty tree:** `git status --porcelain --untracked-files=no`, drop lines whose path starts with `archives/`, refuse if any remain (name the paths). Untracked files do not enter the commit, so ignoring them is safe; staged and unstaged tracked changes are what would make the tag misdescribe the code. No override flag (D-T3 lists only `--force` for size); note the 08.5 sequencing consequence in C-list.
- **Name validation:** `^[a-z0-9][a-z0-9._-]*$`, no `..`, not ending in `.`/`.lock`, not `promoted`. A leading alphanumeric also blocks option injection into git; still pass `--` before paths and never use `shell=True`.

### Pattern 1: Switch-with-pinned-live-value (the repo's own precedent)
**What:** a new strictness is controlled by a config key whose absence means legacy behaviour, and a test pins the live config's value. `allocation_mode` does exactly this (`weekly.py:174-187`; `test_the_live_config_runs_no_regime`). Use `build.fail_loud` the same way so ~10 synthetic `build_monthly_spine` tests (partial sources by design) need no edit, while the live build is strict and deleting the key turns a test red.

### Pattern 2: Pure gate before any write
Compute the verdict from in-memory frames and the provenance dict, raise before `cm.save`. A refused build leaves disk byte-identical, which is the property the 221defc test asserts.

### Pattern 3: Injected paths, call-time defaults
Library functions take `StatePaths`; `default_paths()` reads module constants at call time (so existing `monkeypatch.setattr(platform_ckpt, "PLATFORM_CHECKPOINT_DIR", …)` idioms still work).

### Anti-Patterns to Avoid
- **Importing `DATA_DIR`/`OUTPUT_DIR`/`ROOT` straight from `trading_crab_lib` in `platform/state/`:** adds a 32nd legacy site and fails the ratchet.
- **Reading `TC_*` env in tests of in-process code:** evaluated at import; patch or inject instead.
- **Raising inside `build_core_research_series`:** breaks the direct splice tests; gate in the orchestrator.
- **Loading `nowcaster.pkl` anywhere in `state/`** (archive, verify, promote): P27; verification uses parquet only.
- **`git add -f` of the local archive:** commits live state.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Header-aware trial count | a JSONL parser | `registry.total_trial_count(path)` | the reset-header rule is subtle (`registry.py:166-213`) |
| Serving refit | a second fit recipe | `serving.build_serving_artifacts(cfg, cm=…)` | one function, two callers is the train/serve guarantee |
| Derived-column list | a hard-coded tuple | `splice.derived_columns(cfg)` from config | `publication_lags` is already the authority |
| Tar path safety | ad-hoc string checks only | own member validator **plus** `filter="data"` when available | filter may be missing on old patch levels |

## Common Pitfalls

### P1: Legacy-import ratchet is exactly full
**What goes wrong:** `MAX_LEGACY_IMPORT_SITES = 31` and the scan returns 31. One new `from trading_crab_lib import …` in `platform/` fails CI on all four Python versions.
**How to avoid:** extend the existing import line in `platform/checkpoints.py` (same `ImportFrom` node); derive everything in `state/` from `platform.*` modules.
**Warning signs:** `test_legacy_import_count_does_not_grow` red.

### P2: Session conftest silently redirects two constants
`PLATFORM_CHECKPOINT_DIR` and `HOLDOUT_CHECKPOINT_DIR` are replaced for the whole session; `OUTPUT_DIR`, `ROOT`, snapshots are not. A state test relying on defaults would archive a mix of tmp and real paths. Always construct `StatePaths` over `tmp_path`.

### P3: `snapshots.SNAPSHOT_DIR` is ROOT-based
If `TC_DATA_DIR` points elsewhere, snapshots stay under `ROOT/data/…`. Map the `data/snapshots/platform` arcname to `SNAPSHOT_DIR` explicitly (default-paths builder), not to `data_dir / "snapshots"`.

### P4: `.meta.json` `config_hash` is misleading for the platform
It is the 8-char MD5 of legacy `config/settings.yaml` (`checkpoints.py:189-194, 300`), and `created` is naive local time. The manifest computes its own sha256 of `platform_settings.yaml` and tz-aware timestamps.

### P5: Naive tar.gz is not reproducible
Embedded gzip mtime changes every run (verified). Use the hand-built `GzipFile(mtime=0, filename="")` stack.

### P6: Pre-commit blocks the promote commit on machines with the hook
`check-added-large-files --maxkb=500`. Add the `archives/promoted/` exclusion in the same plan that adds `promote`.

### P7: Git signing/identity in tests
`commit.gpgsign=true` here. Isolate git config and pass `-c` flags (Q10).

### P8: Restore refit overwrites archived live-state files
`build_serving_artifacts` rewrites `asset_returns`, `nowcaster_class_prior`, `returns_by_regime`. Read the archived copies into memory first, compare after.

### P9: Gate must read the *monthly* price frame
Tests (and `build_monthly_spine`) pass `(pd.DataFrame(), monthly_prices)`; checking `daily` would report every ticker missing.

### P10: `reset` deletes tracked files
After `reset` git shows deletions of tracked platform data. `promote` then refuses (dirty). 08.5's order (archive → promote → push tag → untrack/clear) avoids it; document the order in the README section and in `reset`'s confirmation text.

### P11: Existing wording tests
`"unavailable"` appears in two scoreboard tests; `_SUSPENDED_SENTENCE` is pinned in `test_platform_weekly_no_regime.py` (`_D03_SENTENCE`). Add, do not edit, the suspended sentence; update the scoreboard assertions deliberately.

def check_splice_fallbacks(provenance: dict, cfg: dict) -> list[str]:
    bad = []
    for research_name, rec in provenance.items():
        if rec["status"] != "fallback":
            continue
        allowed = set(cfg["splice"][rec["class_name"]].get("allow_fallback") or [])
        resolved = {d["resolved"] for d in rec["sources"].values() if d["position"] != 1}
        if not resolved <= allowed:

    return bad

### Known Threat Patterns
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Tar path traversal / absolute path / symlink escape on restore | Tampering, Elevation | own member validation + `filter="data"` when present; extract to staging, verify, then move |
| Decompression bomb | DoS | compare declared sizes with manifest before extracting; cap total |
| Pickle arbitrary-code execution (P27) | Elevation | pickles never archived, never loaded by `state/`; verification from parquet |
| Live book / account data leaking into git | Information disclosure | basename-based live-state exclusion on promote; `.gitignore` drift test |
| Command/option injection via archive name into git | Tampering | regex `^[a-z0-9][a-z0-9._-]*$`, `--` separators, list-form `subprocess` |
| Half-written or tampered archive trusted by `restore` | Tampering | atomic rename, archive sha + per-file sha verified before use |
| Restoring under mismatched registry/code silently | Repudiation | warnings for commit/config/registry-count mismatch printed, recorded in output |
