## Summary

Scope: the new state tool (`state.py`: archive, list, reset, restore, promote), the fail-loud build gate in
`transforms_monthly.py` and `build_platform_data.py`, `replace_columns` in `merge_preserving`/`CheckpointManager.save`,
the model-free `no_regime` weekly path, and their tests. The 34 tests in the three new test files pass and ruff is clean.

What holds up:
- `restore` is sound. The member path check, regular-file-only rule, manifest-equals-tar check, `filter="data"` extraction, all
  sha256 checks before any move, and the empty-tree precondition work together. I found no traversal or link escape.
- `git` is only called list-form with `cwd=REPO_ROOT`, and nothing pushes.
- Pickles are skipped in `archive` and refused on read in `_check_member_path`.
- `reset` refuses when `archives/` or the registry lies inside `data/` or `outputs/`.
- The G-11 stem list matches the `.gitignore` list exactly.
- The gate's expected-column set matches the real `monthly_raw` columns (45 expected, none missing or all-NaN), so there are no
  false positives on live config.

The concerns are in `promote` (it commits gitignored raw data; its failure path can strand a commit), in `reset` (an irreversible
delete verified only by size), and in the model-free page (it never says which month it scored).

## Critical Issues

### CR-01: `promote` commits gitignored raw vendor data into git history

**File:** `src/trading_crab_lib/platform/state.py:282-291`
**Issue:** The exclusion rule is only `LIVE_STATE_STEMS` plus `weekly_report.md`. Everything else under `data/` and `outputs/` is
re-packed and committed, including `data/raw/` (gitignored at `.gitignore:25`: scraped multpl/macrotrends/FRED raw frames) and
`data/checkpoints/platform_notebook/` (gitignored at `.gitignore:33`). I confirmed this with a throwaway repo: an archive holding
`data/raw/x.csv` was promoted and the file appears in the committed `state.tar.gz` (members were `['data/a.parquet', 'data/raw/x.csv']`).
Once committed and tagged, the data is in history. Removing it takes a history rewrite, and the `model/NAME` tag may already be pushed.
The repo deliberately keeps `data/raw/` out of git, and scraped third-party data has redistribution constraints. The 50 MB cap limits
size but not content. `promote` is documented as "commits a copy without G-11 live state", and this goes further than that contract.
**Fix:** Decide what is promotable from the repo's own ignore rules instead of a hand-copied list, and add the raw/notebook
namespaces. Minimal version:
```python
EXCLUDED_PREFIXES = ("data/raw/", "data/checkpoints/platform_notebook/")
...
if (entry["path"].startswith(EXCLUDED_PREFIXES) or base.split(".")[0] in LIVE_STATE_STEMS
        or base == "weekly_report.md"):
    excluded.append(entry["path"]); continue
```
Better, as one source of truth (it also fixes IN-02): run `git check-ignore --stdin` on the member paths and exclude whatever is
ignored. Add a test with a `data/raw/` file in `WORLD`.

## Warnings

### WR-01: `promote` can strand a commit with no tag, and the tool cannot recover

**File:** `src/trading_crab_lib/platform/state.py:296-305` (and `47`)
**Issue:** `_NAME_RE` accepts names that are not valid git ref components, such as `a..b`, `x.lock` and `foo.`. The tag is created
after the try/except rollback, so a bad ref name or an already existing `model/NAME` tag fails once the commit has landed. Repro
with name `a..b`: `git tag failed: fatal: 'model/a..b' is not a valid tag name.` leaves `chore(archive): promote a..b` committed
with `archives/promoted/a..b/` on disk. A re-run then refuses with "'a..b' is already promoted", so the tool offers no path
forward. The user is left with a committed, untagged state to fix by hand with git.
**Fix:** Validate before any write: run `git check-ref-format refs/tags/model/NAME` in `promote` (or tighten the name regex so it
rejects `..`, a trailing `.` and `.lock`), and refuse early if `git rev-parse -q --verify refs/tags/model/NAME` succeeds. Move
the tag step inside the rollback scope or, on tag failure, print the exact `git tag` command to finish the job.

### WR-02: `reset` deletes irreversibly after only a size-and-name check of the archive

**File:** `src/trading_crab_lib/platform/state.py:174, 249-257`
**Issue:** `archive()` ends with `_check_archive(tmp)`, which compares member names and sizes to the manifest. It never reads
content. The manifest sha256 is computed from a separate read of the file (`_sha256(path)`, line 162) after `tar.add` read it. A
file that changes between the two reads, or a corrupted write, passes the check. `restore` then fails with a hash mismatch at the
moment it is needed. Meanwhile `reset` has already deleted `data/` and `outputs/`, and the pickles it deletes are archived
nowhere. The only guard before the deletes is `(folder / "manifest.json").is_file()`, which is trivially true. Separately,
symlinks are skipped in `archive` (a log warning) but `_walk` includes them, so `reset` unlinks them with no copy.
**Fix:** In `reset`, before deleting, re-hash each tar member (`tar.extractfile(path)` streamed through sha256) and compare it with
the manifest. Better, compute each manifest hash from the bytes that go into the tar. Either way, make `reset` skip or refuse
symlinks it did not archive.

### WR-03: the model-free `no_regime` page never states which month it scored

**File:** `src/trading_crab_lib/platform/report/weekly.py:1135-1156`
**Issue:** `as_of = asset_returns.dropna(how="any").index.max()` is the last month with a return for every tradable asset, and
`scored_as_of_note` is hard-coded to `None`. If one asset's most recent months are NaN (a late ETF print, or a lost source that
`allow_missing_sources` permits), `as_of` silently falls back by months, or years for a dead column. The target mix is then
computed on that older window and the page says nothing. The model path always prints "Scored as of ... N month-ends behind the
newest row" (`_scored_row`). The STALE banner watches `monthly_features` series, not the asset-return completeness, so it does
not cover this. This is the guidance product's honesty rule, applied inconsistently.
**Fix:** Build a note the same way `_scored_row` does and return it as `scored_as_of_note`:
```python
newest = pd.Timestamp(asset_returns.index.max())
lag = _months_between(as_of, newest)
note = (f"Scored as of {as_of.date().isoformat()}, the latest month with a return for every tradable asset"
        + (f" ({lag} month-end{'s' if lag != 1 else ''} behind the newest row)." if lag else " (the newest row)."))
```
The suspended view already renders `scored_as_of_note`. Add a test with a trailing-NaN asset.

### WR-04: `no_regime` gives different books depending on whether a stale nowcaster file exists

**File:** `src/trading_crab_lib/platform/report/weekly.py:1210-1217` (vs. `1230-1235`)
**Issue:** The model-free docstring says the `asset_returns` checkpoint "is serving output and can predate the build". The model
path still reads exactly that checkpoint (`_load_serving_artifact(cm, "asset_returns")`) for `no_regime`. So on a machine with
leftover serving artifacts, the `no_regime` book is computed from possibly stale returns. After a clone or a reset, it is
computed from fresh ones. The path is picked by the presence of a pickle file, not by the config. `no_regime` needs no model in
either case, so the two paths exist for no reason.
**Fix:** In `no_regime` mode always take the model-free derivation (check `mode == "no_regime"` before loading the nowcaster).
That makes one path and removes the stale-returns hazard. This is also the KISS option.

### WR-05: `list_archives` crashes on one unreadable archive, so `list` stops working

**File:** `src/trading_crab_lib/platform/state.py:231-238`
**Issue:** `json.loads(...)` and `(folder / "state.tar.gz").stat()` are unguarded. A truncated or hand-edited `manifest.json`, or a
missing tar, raises `JSONDecodeError` or `FileNotFoundError`. `main` catches only `StateError`, so the user gets a traceback and
cannot list any archive, including the ones needed for `restore`.
**Fix:** Wrap the per-folder read in `except (OSError, ValueError)`, log it at WARNING, and show the row as `unreadable`.

### WR-06: `monkeypatch.undo()` in a test reverts the shared fixture patches onto the real repo

**File:** `tests/unit/test_platform_state.py:339`
**Issue:** `monkeypatch.undo()` undoes every patch made through that `monkeypatch` instance, including those from `state_env`
and `git_env`. After it, `state.REPO_ROOT`, `DATA_DIR`, `OUTPUT_DIR`, `ARCHIVES_DIR` and `REGISTRY_PATH` point at the real
checkout again, and the `GIT_CONFIG_*` environment is restored. The tail of the test only uses the `git_env` helper (which has its
own `cwd`), so it passes today. Any `state.*` call added after the undo, such as `reset` or `archive`, would run against the real
`data/`, `outputs/` and `archives/`. That is the one thing the module docstring says never happens.
**Fix:** Use a scoped patch instead of `undo()`:
```python
with monkeypatch.context() as m:
    m.setattr(state, "MAX_PROMOTE_BYTES", 10)
    with pytest.raises(state.StateError, match="MB|over"):
        state.promote("model-b")
```

## Info

### IN-01: `merge_preserving` stats misreport replaced columns

**File:** `src/trading_crab_lib/checkpoints.py:150-156, 168-172`
**Issue:** `existing` has the replace columns dropped before `cols_added` and `cols_updated` are computed. A replaced column that
was on disk is therefore reported in `cols_added` and never in `cols_updated`. The `Checkpoint %s merged` log line (line 297)
omits `cols_replaced` altogether. The meta sidecar is the audit trail for exactly this incident (221defc), so it should be exact.
**Fix:** Compute `cols_added` and `cols_updated` from the original `existing`, excluding `cols_replaced`, and add a `%d cols
replaced` field to the log line.

### IN-02: `LIVE_STATE_STEMS` duplicates `.gitignore`

**File:** `src/trading_crab_lib/platform/state.py:43-46`
**Issue:** The list matches `.gitignore:43-51` today, but it is hand-copied, so it will drift the next time a per-machine file
is added. The failure mode is committing live book state (G-11) into a promoted archive.
**Fix:** Derive the exclusions from `git check-ignore` (see CR-01), or add a test that parses `.gitignore` and asserts
equality with `LIVE_STATE_STEMS`.

### IN-03: `promote` commits on whatever branch is checked out, including `main`

**File:** `src/trading_crab_lib/platform/state.py:296-297`
**Issue:** Nothing pushes, but a local commit on `main` conflicts with the project rule that work lands on `claude/<description>`
branches and that Glenn merges PRs.
**Fix:** Refuse when `git rev-parse --abbrev-ref HEAD` is `main`, with a message telling the user to switch branches.

### IN-04: `restore` is not atomic after the hash pass, and extraction is unbounded

**File:** `src/trading_crab_lib/platform/state.py:197-211`
**Issue:** The hash pass is all-or-nothing, but the move loop is not. A failure partway through (disk full, permissions) leaves
`data/` partly populated. Re-running `restore` then refuses ("must be empty"), and the suggested `reset` would archive the partial
tree under an auto name. There is also no cap on total decompressed size or file count. The 50 MB cap exists only at promote
time, but promoted archives arrive through git.
**Fix:** On a move failure, remove the files already moved and raise `StateError`. Optionally refuse when the manifest's byte
total exceeds a sane ceiling.

### IN-05: `fallback_splices` ignores `status == "skipped"`

**File:** `src/trading_crab_lib/platform/transforms_monthly.py:418-428`
**Issue:** An optional class with no resolvable source is recorded as `skipped` and produces no research column. The gate covers
this only through `missing_sources`, which `allow_missing_sources` can switch off. When a primary column is allow-listed and its
fallbacks are also gone, the class vanishes quietly: `replace_columns` drops it from `monthly_raw` and the tradable universe
shrinks.
**Fix:** Log a WARNING per skipped class under the gate, or add an explicit entry for it to the problems list unless the class
is named in the allow list.
