<domain>
## Phase Boundary

**Glenn (2026-10-05):** "archive existing datasets and outputs and models so we can essentially cold-start / reset at
any time, plus have the ability to git version control these tagged models."

This phase builds that **capability**, plus the two code preconditions for a cold start:

1. **State tooling:** `archive`, `list`, `reset`, `restore` and `promote` for the platform's generated state (`data/`,
   `outputs/`, local serving models).
2. **A fail-loud build from an empty `data/`.** This is DECISIONS D-08.
3. **The no_regime weekly path runs without any regime model.**

**Out of scope:**

- **The production reset itself:** clearing git, the registry epoch, the test conversion, the learnings. That is
  Phase 8.5, which uses this tooling.
- Rebuilding any model.
- Any registry-bearing measurement.

</domain>

<decisions>
## Implementation Decisions

### Trial budget (ADR-0004)
- **Opening count:** 48, read 2026-10-05.
- **Budget: 0 rows.** Tooling and tests only. No `evaluation.report` run.

### D-T1: Commands and scope
- **One CLI module**, for example `python -m trading_crab_lib.platform.state {archive,list,reset,restore,promote}`. The
  exact name is Claude's discretion.
- **Library functions underneath**, so notebooks and scripts can call them.
- **What an archive covers:**
  - everything under `data/` and `outputs/` that the platform writes;
  - **except `*.pkl`** (D-T5).
- **Paths come from the existing `TC_DATA_DIR` / `TC_OUTPUT_DIR` resolution.** Tests run entirely in `tmp_path` and
  never touch the real namespaces.

### D-T2: Archive and manifest (versioning: local by default)
- **What `archive <name>` writes:** `archives/<name>/`, containing `state.tar.gz` plus `manifest.json`.
- **Manifest contents:**
  - per-file relative path, size and sha256;
  - archive sha256;
  - code commit (`git rev-parse HEAD`) and a dirty-tree flag;
  - `platform_settings.yaml` hash;
  - registry trial count (`total_trial_count()`) and ledger sha256;
  - data date range (first and last index of `monthly_raw` when present);
  - creation time (UTC and CDT);
  - the user's free-text note (`--note`).
- **Naming:** `[a-z0-9._-]+`. An existing name is refused, because archives are immutable.
- **`archives/` is gitignored**, except promoted archives (D-T3).
- **`list`** prints name, date, size, promoted yes/no, code commit and trial count.

### D-T3: `promote <name>`: git version control for tagged models
- **What it does:**
  - commits `archives/<name>/` into git (force-add past the ignore rule, or a tracked `archives/promoted/` subtree;
    Claude's discretion);
  - creates the annotated tag `model/<name>` on that commit, with the manifest summary as the tag message;
  - prints the push command, but **does not push by itself**.
- **Refuses:**
  - **live book state** (G-11 files: `executed_weights`, `regime_belief`, `allocation_mode`, `hysteresis_state`,
    `nowcaster_class_prior`, `asset_returns`, `returns_by_regime`, `weekly_report.md`). A promoted archive is rebuilt
    without them, or the tool refuses with a clear message, whichever is simpler, and the manifest records the
    exclusion;
  - any `*.pkl`;
  - an archive over a size guard (default 50 MB, configurable; `--force` overrides with a warning);
  - a dirty working tree outside `archives/`.

### D-T4: `reset`: always auto-archive, never the registry
- **Steps:** `reset` first writes `archive auto-<UTC timestamp>` (local, unpromoted), then empties the platform's
  `data/` and `outputs/` namespaces. It prints the archive name to restore from.
- **It never touches `registry/`.** A registry epoch stays a separate, deliberate action with its own ADR (8.5).
- **Confirmation:** needs `--yes`, or an interactive confirm. The confirm states what will be emptied and the
  auto-archive name.

### D-T5: `restore <name>`: no pickles; refit and verify
- **Precondition:** restores into **empty** namespaces only. If they are not empty, it refuses and suggests `reset`,
  which auto-archives.
- **Checks before extracting:**
  - every file's sha256 is verified against the manifest;
  - a code-commit or config-hash mismatch against HEAD is printed as a **warning**, not an error. Restoring an old
    archive under new code is allowed but flagged.
- **Pickles are never archived** (P27). After extracting, `restore` runs the existing serving refit command
  (`SERVING_BUILD_COMMAND` in `report/serving.py`) only when the archive held serving outputs, then verifies the refit
  against the manifest. The verification method is Claude's discretion, e.g. served posteriors on the archived data
  equal the archived belief at rel 1e-9, or a documented equivalent.
- A restore that cannot refit, for example because no serving state was archived, says so and leaves the page to run
  in no_regime mode.

### D-T6: Fail-loud build from empty (DECISIONS D-08)
- From an empty `data/`, `scripts/build_platform_data.py` (one command) builds raw → splice → features → holdout
  carve.
- **Merge-on-save fills raw source columns only**, never derived or spliced ones.
- **A single-source splice resolving to a fallback candidate fails the build**, unless the config explicitly allows
  that fallback for that class.
- **Any failed source fetch fails the build**, naming the source and how to retry.
- **The closing hint no longer invites a backtest re-run**, because that rewrites evaluation outputs.
- The build writes a provenance manifest beside the data: per source, fetch time, rows, date range and resolved splice
  candidate. It is reused by D-T2.
- **A regression test reproduces the 221defc failure** (a fetch drops gold_spot, the old disk column is present) and
  shows the build now fails instead of producing a −98% month.

### D-T7: The no_regime weekly path needs no regime model
- In `allocation_mode: no_regime`, assembling the weekly page needs none of these:
  - L1 labels;
  - `config/regime_labels.yaml`;
  - a fitted nowcaster;
  - a served belief.
- If any is touched today, it becomes optional in that mode. The page then shows "Regime view: suspended" and, with no
  backtest outputs present, "Scoreboard: not yet measured" instead of erroring.

### Added after research (Glenn, 2026-10-05; RESEARCH.md § Conflicts C1–C13)
- **D-T8 (C2): a failed FRED daily fetch (DAAA, DBAA) fails the build.**
  - D-08 supersedes ruling A1.
  - The build still writes the other checkpoints, then exits 1, naming the source and the retry command.
  - The pinned A1 test flips with a dated note.
- **D-T9 (C3): the strictness switch.**
  - The gates are governed by `build.fail_loud`, which is `true` in the live `config/platform_settings.yaml` and pinned
    by a test, the same pattern as `allocation_mode`. If the key is absent, legacy behaviour is kept, so the synthetic
    `build_monthly_spine` tests and `_pit_cfg` stay untouched.
  - **Escape hatch:** `build.allow_missing_sources: []`, an explicit and logged per-source allowance for a flaky source
    such as macrotrends or `^GSPC` on the Mac. It never silently splices: an allowed missing source still cannot
    trigger a fallback splice unless that class's fallback is also explicitly allowed.
- **D-T10 (C8): archive and reset scope is all of `data/` and `outputs/`**, legacy included. This supersedes the
  "platform writes" wording in D-T1. Exclusions:
  - the serving model pickles (`data/checkpoints/platform/*.pkl`) are never archived. They are refit on restore (D-T5);
  - legacy `*.pickle` data files (P25) may ride in a **local** archive as opaque bytes. The tool never loads them, and
    they are **never promoted** (P27: no pickle arrives through git);
  - `archives/` and `registry/` sit outside both trees, so reset never touches them.
- **Accepted research recommendations (Claude's discretion, recorded):**
  - **C1:** no new legacy-import sites (ratchet at 31). Extend `platform/checkpoints.py:20` instead.
  - **C4:** the manifest carries a `serving` block (class prior captured from parquet at archive time), so restore can
    verify a refit even from a promoted archive. A restore from a promoted archive gives a cold weekly state (the A-15
    note is expected).
  - **C5:** accepted.
  - **C6:** add a second suspended sentence. The pinned `_SUSPENDED_SENTENCE` is not edited.
  - **C7:** model-free `as_of` is the latest month complete in every `asset_returns` column. Use the checkpoint if
    present, else derive it from `monthly_raw`.
  - **Promote layout:** a tracked `archives/promoted/<name>/` subtree, with `.gitignore` lines `archives/*` and
    `!archives/promoted/`.
  - **Deterministic tar:** a hand-built `GzipFile(mtime=0)` with sorted members.
  - **Safe extraction:** `filter="data"` plus our own member validation.
  - **Pre-commit:** `.pre-commit-config.yaml` excludes `^archives/promoted/` from the large-file hook (C11).
  - **C10:** reset makes git dirty and promote then refuses. That is intended, and the order is documented.

### KISS revision (Glenn, 2026-10-05; DECISIONS P-07). Supersedes D-T1..D-T10 where they conflict
Glenn: "Keep-it-simple-stupid … human-readable, human-editable, human-testable by a single human user."
"Delete current pickles, it's ok to lose these."

- **K-1. Two plans, each ≤150 lines.**
  - Plan 01: the fail-loud build and the page from empty.
  - Plan 02: the state tool plus docs.
- **K-2. The tool is one file:** `src/trading_crab_lib/platform/state.py`. It holds library functions plus a small
  argparse `main()`, is run as `python -m trading_crab_lib.platform.state`, and is not a package. Aim for ≤300 lines.
- **K-3. A plain manifest (`manifest.json`)** holds:
  - name, note;
  - created time (UTC and America/Chicago);
  - git commit plus a dirty flag;
  - registry trial count;
  - a list of `{path, bytes, sha256}` for every file.

  Dropped: the archive-level sha, config hash, data date range and serving block. The commit already pins config, and
  the file list shows the data.
- **K-4. Plain `tarfile` "w:gz", no deterministic-tar machinery.** The per-file sha256 values are the integrity record.
- **K-5. No pickle (`.pkl`, `.pickle`, `.joblib`) in any archive, local or promoted.** One rule, so the legacy
  `.pickle` split is gone. `reset` deletes them, and its output lists them. Glenn accepts losing them.
- **K-6. `reset NAME? --yes`.**
  - `--yes` is required; there is no interactive or typed confirm.
  - It writes `auto-<UTC stamp>` (or the given name) first, then deletes the contents of `data/` and `outputs/`,
    keeping `.gitkeep`. It never touches `registry/` or `archives/`.
- **K-7. `restore NAME` (supersedes D-T5's refit and 1e-9 verification).**
  - Refuses unless `data/` and `outputs/` are empty.
  - Extracts with `tarfile` `filter="data"`, which blocks path traversal, absolute paths and links. If the interpreter
    lacks it, restore refuses.
  - Checks each file's sha256 against the manifest before moving it into place. A different commit only warns.
  - **No refit and no model verification.** The no_regime page runs without a model (D-T7). Restore prints the
    serving build command for anyone using `regime_tilt`.
- **K-8. `promote NAME`.**
  - Writes `archives/promoted/NAME/`: the archive's tar re-packed **without G-11 live-state files**, plus the
    manifest.
  - Then `git add` + commit + annotated tag `model/NAME`.
  - Refuses a dirty tree. Never pushes. A fixed 50 MB size limit, with no flag.
  - Tests run in a throwaway `git init` repo.
  - `.gitignore`: `archives/*` and `!archives/promoted/`. Pre-commit large-file hook excludes `archives/promoted/`.
- **K-9. Fail-loud build.**
  - **Config:** two keys only: `build.fail_loud: true` (pinned) and `build.allow_missing_sources: []`. A fallback splice
    is refused unless its primary source column is listed in `allow_missing_sources`. There is no separate
    `allow_fallback`.
  - **D-T8 stands:** a failed FRED daily fetch exits 1.
  - **No `build_provenance.json`.** The existing `splice_provenance.json` and `.meta.json` files suffice.
  - **Merge fix:** derived and spliced columns are replaced, never filled from disk.
  - **One plain 221defc regression test,** with no mutation-proof scaffolding.
- **K-10. Model-free no_regime page (D-T7): unchanged.** It is what makes a reset usable. Keep the code change minimal.
- **K-11. Tests:**
  - one behaviour test file per plan topic (`test_platform_build_fail_loud.py`, `test_platform_weekly_model_free.py`,
    `test_platform_state.py`);
  - no drift-guard or mutation tests;
  - legacy-import ratchet stays at 31.

## Existing Code Insights

- **Today's state is small:**
  - `data/` is 9.0 MB and `outputs/` 3.0 MB;
  - the tracked platform set is about 6 MB;
  - a tar.gz of both is 9.7 MB, so promoted archives in git are practical at this scale.
- **Serving pickles:** `nowcaster.pkl` in the tracked namespace is machine-local and gitignored, rebuilt by
  `SERVING_BUILD_COMMAND`.
- **Live state files:** 08.3 found which ones the weekly writes; the G-11 list is in `.gitignore`.
- **`CheckpointManager`:**
  - writes parquet plus `.meta.json`;
  - merge-on-save is on by default for raw ingest checkpoints (commit b525566);
  - the migration script uses `merge=False`.
- **Tests:** the platform suite runs CI on Python 3.10–3.13 with pandas 2 and 3, and has 2699 tests today. New
  tooling tests must not need network or real data.

<specifics>
## Specific Ideas

- **The intended 8.5 flow, so the contract fits:**
  1. `archive pre-reset-2026-10 --note "post-08.3, before clean-slate reset"`;
  2. `promote pre-reset-2026-10`, giving the git tag `model/pre-reset-2026-10`;
  3. push the tag;
  4. untrack and clear;
  5. later, on the Mac: `reset` → fresh build → page.
- **The tool should make "start over" a habit, not an event.** A typical later use: before trying a rebuild module, run
  `archive before-M5`, then experiment, then either `promote` or `reset` + `restore before-M5`.

</specifics>
