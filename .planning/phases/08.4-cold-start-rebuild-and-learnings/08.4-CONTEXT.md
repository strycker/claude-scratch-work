<domain>
## Phase Boundary

**Reframed by Glenn (2026-10-05).** This is a **production reset**, not a cold-start *test*.

The phase:

1. Clears out the models, labels, state and every generated artifact, so that no model lives in git.
2. Proves that the code can start from a truly empty checkout:
   - fresh data pull;
   - fail-loud build;
   - the MVP-1 no-regime weekly page.
3. Writes down what we learned, so that Phase 9+ can rebuild M0→M7 **module by module in the target `trading-crab`
   repo**, each step human-gated.

**Out of scope:**

- Rebuilding any regime model, whether labeler, nowcaster or tilt.
- E-11, the month-end vol inputs, which becomes M3 in the rebuild.
- The L2 recipe and distinct-output check, which becomes M6.
- CR-02, A-03 and REG-01.
- A model-artifact tagging and storage mechanism (deferred).
- Any registry-bearing measurement.

</domain>

<decisions>
## Implementation Decisions

### Trial budget (ADR-0004)
- **Opening count:** `total_trial_count()` = **48**, read 2026-10-05.
- **Budget: 0 rows.** The reset spends no trials, and the page's scoreboard shows "not yet measured since reset".
- **After the reset:** the count is **0** (see D-03).

### D-01: Freeze, then clear (Glenn: "everything out, raw too")
- **Freeze first.** Before deleting anything, create the annotated git tag `archive/pre-reset-2026-10` at the
  post-08.3 main HEAD (f15fe14 or later) and push it. Every deleted artifact and record stays retrievable from that
  tag. Name the tag in DECISIONS and the README.
- **Untrack and delete:**
  - all of `data/`: platform checkpoints (raw included), `data/snapshots/platform`, `data/holdout`, and the legacy
    quarterly pickles and xlsx (P25);
  - all of `outputs/`: `outputs/reports/platform` including `pit_08.x/`, and `outputs/reports/model_metrics`.
- **Gitignore** `data/` and `outputs/` wholesale, with narrow re-includes only for any `.gitkeep`. Nothing generated
  can be committed by accident again (the lesson of G-11 and 221defc).
- **Notebooks:** strip outputs from `notebooks/platform/P1–P9` and from any notebook whose outputs embed real-data
  results. Keep every markdown sign-off cell **verbatim** as the record of past judgments.
- **Not touched:**
  - `legacy/`, the submodules, `config/` (except `config/regime_labels.yaml` per D-05), and code;
  - `registry/`, which is handled separately in D-03.

### D-02: The build works from empty and fails loud (absorbs DECISIONS D-08)
- From an empty `data/`, `scripts/build_platform_data.py` (one command, documented) produces every input the
  no-regime page needs: raw → splice → features → holdout carve.
- No merge-on-save from a missing or prior disk copy.
- **Merge-on-save fills raw source columns only**, never derived or spliced ones.
- **A single-source splice that resolves to a fallback candidate fails the build**, unless the config explicitly
  allows that fallback for that class.
- **Any source that fails to fetch fails the build**, naming the source and the command to retry.
- **The closing hint must not invite a backtest re-run** that would write evaluation outputs.
- **Provenance manifest.** The build writes a manifest beside the data:
  - per source: fetch timestamp, row count, first and last date, resolved splice candidates;
  - a content hash.

  It is the cold-start provenance record. It is generated and untracked, like the data.

### D-03: Registry: true-zero epoch (Glenn's explicit choice)
- Archive `registry/trials.jsonl`, all 48 trials, intact as `registry/archive/trials-pre-8.4-reset.jsonl`.
- Start a new ledger with a provenance header: `prior_genuine_trials = 0` and a reset reason naming this decision.
- **New ADR `platform_design/adr/0005-registry-true-zero-reset.md`** records:
  - the choice, and that it was Glenn's;
  - **the caveat:** the 48 prior trials ran on the same 1972–2020 development data, which a reset does not make
    unseen, so DSR hurdles right after the reset understate the true multiple-testing burden;
  - **the guard:** the 2021+ holdout is still untouched and remains the decisive check at design freeze.
- **Disclosure rule:** every DSR or hurdle line printed after the reset (report, page, notebooks) carries a one-line
  epoch note, e.g. "registry epoch reset 2026-10 (true zero; 48 prior trials not carried — ADR-0005)".
- The registry stays **tracked**. It is the honesty record, not a model.

### D-04: Tests: CI on fixtures, real-data tests local-only
- About 29 test files read tracked data or outputs.
- **Real-data tests** that are still meaningful (point-in-time lags, month-end P&L, no-leak, reproduction of a fresh
  build):
  - keep them, marked `@pytest.mark.realdata`;
  - auto-skip them with a clear reason when `data/` is absent;
  - Glenn runs them on the Mac after a build.
- **Record tests** that pin retired numbers (the 8.1/8.3 records, tracked KPI and curve pins, `pit_08.x`) are retired.
  Their records live in the archive tag. List each one in the SUMMARY with its reason. **Nothing is deleted silently.**
- **Coverage that CI loses** is replaced with small committed **synthetic fixtures** under `tests/fixtures/`, where the
  behavior matters (not the numbers).
- **Gate:** the full suite is green on Linux CI (pandas 2 and 3) with no data present, and green on the Mac with
  `realdata` included after a build.

### D-05: MVP-1 runs from empty without any regime model
- In `allocation_mode: no_regime` the weekly path must not need:
  - L1 labels;
  - `config/regime_labels.yaml` pins;
  - a fitted nowcaster or a served belief.
- If it touches any of these today, make that dependency optional in no_regime mode.
- **Regime view:** stays "suspended".
- **Scoreboard:** "not yet measured since reset (registry epoch 0)".
- **Tripwire:** computed from the fresh pull.
- **Kept:** the STALE banner, the target table and the trades.
- **`config/regime_labels.yaml`:** pins the retired labels. Archive it in the tag and remove it, or empty it with a
  pointer, whichever the code tolerates. Claude's discretion.

### D-06: Exit = clean slate plus MVP-1 from empty (the phase's testable gate)
On Glenn's Mac, from a **fresh clone**, the documented commands (build → page) succeed. Two runs give an identical
page. N4 (P7) runs top to bottom on the fresh build and Glenn signs it. The 08.3-close live-state backup is **not**
restored first. It is a true cold start, and the A-15 "mode changed" note or first-run note is expected.

### D-07: Learnings and the Phase 9 order (plan 3)
- Fold this phase's and 8.1–8.3's learnings into:
  - `REBUILD-FROM-SCRATCH-GUIDE.md`;
  - `platform_design/MODULE-MAP.md`;
  - `MIGRATION-PLAN.md`;
  - `DECISIONS.md`: rows for the reset (G-12), the registry epoch (honesty section, pointing to ADR-0005), D-08 marked
    built, and E-11 and L2 retargeted to the rebuild modules.
- **ROADMAP:** restructure Phase 9 into **9.x per module**: the M0 skeleton, then M1 data spine, …, M7, in the target
  repo, each with its notebook and Glenn's sign-off.
- **Rebuild items placed:** E-11 at M3; L2 recipe and distinct-output check at M6; CR-02 at M5; A-03 and REG-01 at M9+.
- **Model-artifact tagging** ("models not in git unless tagged") is a deferred item for the M0/M5 rebuild phases.

  2. D-01 + D-03 + D-04: freeze, clear, registry epoch, tests;
  3. D-07 plus the Mac gate D-06.
