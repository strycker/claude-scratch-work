A **production reset**, not a cold-start test (Glenn, 2026-10-05): "a completely clean restart … not git version
controlling the actual models unless we tag them somehow … the capability of starting over from a clean slate".

1. Nothing generated lives in git any more: no data, no outputs, no notebook outputs.
2. The suite is green with no data present (Linux CI, pandas 2 and 3).
3. The registry starts a true-zero epoch (ADR-0005).
4. From a fresh clone on Glenn's Mac, the documented commands build the data and write the MVP-1 page.
5. The learnings and the Phase 9.x order are written down.

**Out of scope:** rebuilding any regime model (labeler, nowcaster, tilt); E-11 (M3); the L2 recipe (M6); CR-02 (M5);
A-03 and REG-01 (M9+); any registry-bearing measurement; new tooling (8.4 built it).

## Implementation Decisions

### Dropped in the KISS revision (2026-10-10)
- **D-02 (fail-loud empty build):** shipped in 8.4 (DECISIONS D-08).
- **Most of D-05 (page with no model):** shipped in 8.4 and passed Glenn's UAT on 2026-10-09.
- **Retiring `config/regime_labels.yaml`:** it is legacy quarterly config (`trading_crab_lib/regime.py`,
  `trading_crab/pipeline.py`); the platform never reads it. Left alone.
- **The P7 (N4) notebook as the exit gate:** serving needs the `regime_labels` checkpoint, which the reset deletes and
  the build does not recreate. The gate is the build plus the page (D-06).
- **An epoch note on every DSR or hurdle line now:** nothing prints a DSR line until the first budgeted run in
  Phase 9. The reset is recorded once, in ADR-0005 and the ledger header. That first run adds the line.
- **`archive` + `promote` of the pre-reset tree:** replaced by a git tag (D-01).

### D-01: Freeze with a tag, then clear
- **Freeze (Glenn, 2026-10-10: "Tag only"):** the annotated tag `model/pre-reset-2026-10` on `4e49652`, main after
  PR #162 merged, the last commit before any deletion. Git history already holds every byte of the 88 tracked files
  (6.2 MB), so no tarball is promoted. The tag is created and its message written. The session's git proxy refuses
  tag pushes (and the GitHub API write path), so **Glenn pushes it from the Mac** before merging 8.5:
  `git fetch origin && git tag -a model/pre-reset-2026-10 4e49652 -m "pre-reset-2026-10: last tree before the 08.5
  reset" && git push origin model/pre-reset-2026-10`. Retrieval: `git checkout model/pre-reset-2026-10 -- data outputs`.
- **Live book state** (G-11) was never tracked. On the Mac, `python -m trading_crab_lib.platform.state archive
  pre-reset-2026-10` before pulling keeps it locally.
- **Delete from git** all 88 tracked files under `data/` and `outputs/`: platform checkpoints (raw included),
  `data/snapshots/platform`, `data/holdout`, the legacy pickles and xlsx at `data/` root, and everything under
  `outputs/reports/` (`pit_08.x/`, `joint_lift/`, `trials/`, `stability/`, `track_a/`, `model_metrics/`).
- **Gitignore** `data/` and `outputs/` wholesale, re-including only `.gitkeep` files the code or docs rely on.
- **Notebooks:** strip outputs from `notebooks/platform/P1–P9`. Keep every markdown sign-off cell verbatim.
- **Not touched:** `legacy/`, the submodules, `config/`, code (except what D-04 needs), `registry/` (D-03).

### D-03: Registry: true-zero epoch (Glenn's explicit choice, 2026-10-05)
- Archive `registry/trials.jsonl` (48 trials) intact as `registry/archive/trials-pre-8.5-reset.jsonl`.
- Start a new ledger with a provenance header: `prior_genuine_trials = 0` and a reset reason naming ADR-0005.
  `total_trial_count()` reads 0 afterwards.
- **ADR-0005** (`platform_design/adr/0005-registry-true-zero-reset.md`): the choice and that it was Glenn's; the caveat
  (the 48 trials ran on the same 1972–2020 development data, which a reset does not make unseen, so DSR hurdles right
  after the reset understate the multiple-testing burden); the guard (the 2021+ holdout is untouched and decides at
  design freeze); the rule that the first post-reset DSR line carries the epoch note.
- The registry stays tracked. It is the honesty record, not a model.

### D-04: Tests: green with no data
- 38 test files read tracked data or outputs today. Each is classified:
  - **Lasting property** (point-in-time lags, holdout fence, month-end P&L, no-leak): keep, mark
    `@pytest.mark.realdata`, auto-skip with a clear reason when the data is absent. Glenn runs them on the Mac after a
    build.
  - **Record pin** (8.1/8.3 numbers, tracked KPIs and curves, `pit_08.x`, the scoreboard and parity pins): retire. The
    record lives in the tag. Each retired test is listed in the SUMMARY with its reason; nothing is deleted silently.
  - **Behaviour that only happened to use tracked data:** move it onto a small synthetic fixture under
    `tests/fixtures/` (or an existing synthetic world), behaviour not numbers.
- `tests/unit/tracked_record.py` goes with the tracked data.
- **Order:** this lands before the deletion, so CI never goes red.
- **Gate:** the full suite is green with `data/` and `outputs/` absent (pandas 2 and 3), and on the Mac with `realdata`
  included after a build.

### D-05: The page from empty (leftover)
- Verify on the fresh clone only. The scoreboard reads "not yet measured", the regime view "suspended". No new code
  unless the fresh clone shows a dependency 8.4's UAT (which ran from an empty `~/tc-cold`) did not.

### D-06: Exit gate (Glenn's Mac, fresh clone)
- `git clone` → install → `python scripts/build_platform_data.py` (with `--allow-missing gold_spot,wti_crude,
  sp500_close_me` on the VPN) → `python -m trading_crab_lib.platform.report.weekly` twice → the two pages are identical
  apart from the run date → `pytest -m realdata`.
- The first post-reset page is the new baseline. Its book may differ from 34.4/34.4/19.5/11.7 because the fresh pull
  revises history (and gold is now the World Bank series, D-09). Report the difference; it is not a failure.

### D-07: Learnings and the Phase 9 order
- Fold the 8.1–8.5 learnings into `REBUILD-FROM-SCRATCH-GUIDE.md`, `platform_design/MODULE-MAP.md`,
  `MIGRATION-PLAN.md` and DECISIONS (a reset row; the registry epoch in the honesty section pointing to ADR-0005; E-11
  and the L2 recipe retargeted to M3 and M6).
- **ROADMAP:** restructure Phase 9 into 9.x, one module per phase in the target `trading-crab` repo: M0 skeleton (carries
  the state tool), M1 data spine, M2 features, M3 allocator + backtest (E-11), M4 weekly, M5 labeler (CR-02),
  M6 nowcaster (L2 recipe), M7 tilt vs ablation; M9+ for A-03 and REG-01. Each with its notebook and Glenn's sign-off.

### Plan split

   behaviour coverage would be lost; drop `tracked_record.py`. Suite green with `data/` and `outputs/` moved away.
2. **Reset (D-01, D-03):** delete and gitignore; strip notebook outputs; registry epoch + ADR-0005; Mac instructions.
3. **Learnings (D-07) and the Mac gate (D-06).**
