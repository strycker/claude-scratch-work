## Warnings

### WR-01: code_version() reports a clean tree when `git status` fails or times out

**File:** `src/trading_crab_lib/platform/code_version.py:21-26, 35-40`

**Issue:** `_git()` collapses three different outcomes into `None`: a non-zero exit, a `TimeoutExpired`, and a missing git. The function then reads `None` as "no output". As a result:

- `dirty = "" if _git("status", ...) is None`, so a status that failed or ran past 10 s is printed as a clean tree. The line shows no `+ uncommitted changes` marker.
- If `rev-parse --short HEAD` times out, for example on a cold, slow filesystem, the line says `not a git checkout` about a real checkout.

G-16 exists so that Glenn trusts the line before trusting a run, so a false "clean" defeats its purpose. I reproduced this by forcing `_git("status", ...)` to return `None` on a dirty repo. The output was `Code: main @ 7755cc5 — /tmp/...`, with no dirty marker.

**Fix:** Make the result three-way and say "unknown" rather than guessing:
```python
status = _git("status", "--porcelain", "--untracked-files=no")
dirty = " + uncommitted changes" if status else (" + status unknown" if status is None else "")
```
Have `_git` return `""` for a successful run with empty output (it already does), and `None` only on failure. Report a failed `rev-parse HEAD` as `Code: git unavailable (<reason>) — {_HERE}`, not "not a git checkout".

### WR-02: A non-editable install inside the repo's `.venv` is reported as the checkout's code

**File:** `src/trading_crab_lib/platform/code_version.py:9-10, 18, 35-42`

**Issue:** The docstring promises that the line "names the checkout whose code is executing". Git runs in `_HERE`, the directory of the installed module. For a regular (non-editable) install into the in-repo `.venv/` (which exists here and is gitignored), `_HERE` is `.venv/lib/.../site-packages/trading_crab_lib/platform`. Git discovers the enclosing repo and prints its branch and HEAD, even though the code that runs is whatever was copied into site-packages at install time.

A stale non-editable install is one of the most common ways to "run the wrong code", and here the line actively vouches for it. I reproduced it: a copy of `code_version.py` in an ignored `.venv/.../site-packages/...` printed `Code: main @ <sha> — <repo>`.

The trigger is plausible: `pip install "src/trading_crab_lib/[all]"` without `-e`, or a `uv pip install` of a wheel.

**Fix:** Verify that the module file is a tracked file of the checkout before attributing it:
```python
if _git("ls-files", "--error-unmatch", Path(__file__).name) is None:
    return f"Code: installed copy, not a checkout — {_HERE}"
```
`ls-files` runs with `cwd=_HERE`, so the relative name works. Alternatively, use `git check-ignore -q .` and treat exit 0 as "installed copy".

### WR-03: A partial budgeted-run record is reported as "no budgeted run has written its record here yet"

**File:** `src/trading_crab_lib/platform/report/scoreboard.py:141-154`

**Issue:** The `FileNotFoundError` branch now asserts that no run has happened, and it logs at INFO. That is only true when all three files are missing. Two failure scenarios:

- **A run crashed after spending its rows.** `evaluation/report.py` appends its registry rows inside `run_backtest` / `no_regime_ablation` (lines 896, 931), before it writes the artifacts (lines 1084-1086). A run that crashes or is interrupted after the KPI table is written, but before both curve parquets exist, leaves spent rows and a half-written record.
- **A curve file was deleted.** The same happens if someone deletes one curve file.

In both cases the weekly page then says "no budgeted run has written its record here yet; missing backtest_equity_curve_ablation.parquet", at INFO level. That tells the operator the opposite of the truth: rows were spent, and the record is broken.

The new `KeyError` ("incomplete") branch is also untested. Only the "KPI file missing" case has a test (`test_missing_kpi_parquet_is_an_unavailable_line`).

**Fix:** Classify by what is present, and keep the WARNING for any partial record:
```python
present = [p for p in (_KPI_FILE, *_CURVE_FILES.values()) if (reports / p).exists()]
if not present:
    board["reason"] = "no budgeted run has written its record here yet"
    log.info(...)
else:
    board["reason"] = f"the budgeted run's record under {reports} is incomplete (missing {missing})"
    log.warning(...)
```
Add tests for "KPI present, a curve missing" and for a `KeyError` (a KPI table without a `leg` row).

### WR-04: The ADR-0004 trial-row budget check was retired with nothing replacing it

**File:** `tests/unit/test_platform_gate_tiers.py:191-194` (removed test `test_the_live_trial_count_is_what_feeds_the_hurdle` and the constant `DECLARED_TRIAL_CEILING`)

**Issue:** The retired test made two assertions:

- (a) `total_trial_count() <= DECLARED_TRIAL_CEILING`, which was the only mechanical enforcement in the suite of "each phase declares its row budget" (CLAUDE.md, ADR-0004);
- (b) the hurdle at the live count is `>= RECORDED_HURDLE`.

The retirement note justifies dropping both, but only (b) breaks at the true-zero epoch (`expected_max_sharpe(0, ·) == 0`). Assertion (a) still holds with a declared ceiling of 0 plus whatever the next phase declares. A grep for `ceiling` or `budget` in tests and the platform package finds no other check.

Failure scenario: a Phase 9 run that spends more registry rows than declared now passes the full suite silently.

The note's claim that "the monotone property stays covered by test_more_trials_raise_the_bar" is true, but that test covers a different property.

**Fix:** Keep (a) with the epoch's declared ceiling, and drop only (b):
```python
DECLARED_TRIAL_CEILING = 0  # true-zero epoch (D-03, ADR-0005); the next budget declaration edits this line

def test_the_live_trial_count_stays_within_the_declared_budget(self):
    assert total_trial_count() <= DECLARED_TRIAL_CEILING, "exceeding it needs a written budget amendment first (ADR-0004)"
```

### WR-05: The realdata hook raises a "-m realdata" UsageError for unrelated `-m` expressions

**File:** `tests/conftest.py:54-58`

**Issue:** The hook raises when `markexpr` is any non-empty string and every remaining item is a realdata test. It does not check that the expression actually asks for realdata.

Reproduced on this machine, which has no built data: `pytest -m "not network" tests/unit/test_platform_monthly_spine_consistency.py` aborts with `ERROR: -m realdata needs built data under data/ ...` and exit status non-zero. The user never mentioned realdata; without `-m` the same selection skips cleanly. Any file or `-k` selection that contains only realdata tests behaves the same way, combined with any `-m` filter.

**Fix:** Raise only when the expression selects realdata:
```python
expr = config.getoption("markexpr") or ""
if "realdata" in expr and "not realdata" not in expr and len(marked) == len(items):
    raise pytest.UsageError(...)
```
Alternatively, compile the expression with `_pytest.mark.expression.Expression.compile(expr)` and evaluate it with `{"realdata"}` as the only mark.

### WR-06: test_platform_code_version is not isolated from the developer's git config, and it errors when git is missing

**File:** `tests/unit/test_platform_code_version.py:12-27, 51-54`

**Issue:** The `repo` fixture runs `git init -b` and `git commit` with the user's global and system config. With `commit.gpgsign=true` set globally (common with 1Password or SSH signing on a Mac), three of the four tests error. I reproduced this with `GIT_CONFIG_GLOBAL` pointing at a config with `commit.gpgsign=true`, and got `1 passed, 3 errors`.

There are three more gaps:

- There is no `shutil.which("git")` skip, so on a machine without git the fixture raises `FileNotFoundError` and the tests error instead of skipping.
- The branch that matters most on such a machine (`_git` catching `FileNotFoundError`) is itself untested, and so is the timeout branch.
- Inherited `GIT_DIR` or `GIT_INDEX_FILE` (for example when pytest runs from a pre-commit hook) would also redirect these calls.

`test_platform_state.py::git_env` (lines 271-286) already shows the right pattern.

**Fix:** Mirror `git_env`:
```python
if shutil.which("git") is None:
    pytest.skip("git is not installed")
monkeypatch.setenv("GIT_CONFIG_GLOBAL", "/dev/null")
monkeypatch.setenv("GIT_CONFIG_NOSYSTEM", "1")
for var in ("GIT_DIR", "GIT_WORK_TREE", "GIT_INDEX_FILE"):
    monkeypatch.delenv(var, raising=False)
_git(tmp_path, "config", "commit.gpgsign", "false")
```
Also add two tests:
- monkeypatch `subprocess.run` to raise `FileNotFoundError`, and assert the "not a git checkout" line;
- monkeypatch it to raise `TimeoutExpired`, and assert the "status unknown" line from WR-01.

### WR-07: Registry rows record the shell's cwd commit, which can contradict the new code line

**File:** `src/trading_crab_lib/platform/honesty/registry.py:53-63` (pre-existing; becomes inconsistent with the G-16 line added to `evaluation/report.py:1134`)

**Issue:** `code_version()` resolves git from the package directory. `registry._git_sha()` runs `git rev-parse HEAD` with no `cwd`, so it reads the repository of the shell's working directory.

Failure scenario: Glenn runs `python -m trading_crab_lib.platform.evaluation.report` from `~` or from a second clone against an editable install of the first.

- The console prints `Code: claude/x @ abc123 — /path/A`.
- Every registry row it appends records `git_sha` "unknown" (cwd is not a repo) or clone B's HEAD.

The registry row is the decision-bearing provenance, and it is append-only, so a wrong SHA cannot be corrected. `_git_sha` also has no timeout, and it records no dirty flag.

**Fix:** Give `_git_sha` the same anchoring: `subprocess.run([...], cwd=Path(__file__).resolve().parent, timeout=10, ...)`, and catch `subprocess.TimeoutExpired`. Better, expose a shared `head_commit()` from `code_version.py` and use it in `registry.py`, `snapshots.py` and `state.py`, which now hold four separate git helpers.

### WR-08: On a `--allow-missing` (VPN) build, the realdata gate skips the exact raw-to-features rebuild check, which does not depend on the missing columns

**File:** `tests/unit/test_platform_pnl_returns.py:697-700, 722-735`

**Issue:** `test_features_rebuilt_from_the_tracked_raw_equal_dev_and_holdout_exactly` calls `_require_month_end_columns(raw)` and skips whenever a month-end column is absent or all-NaN. Its actual check is that `features_from_raw(raw, cfg)` equals the saved dev and holdout `monthly_features` exactly. That check does not use the month-end columns: the test asserts they never reach the features.

It is the only realdata test that compares every feature column of a fresh build against its raw source. `test_platform_monthly_spine_consistency.py` checks only the three passthrough columns. The 08.5-03 Mac gate ("8 passed + 6 month-end skips") therefore ran without it. A raw/features divergence in a non-passthrough column (the 23-year `oil` incident class) would have passed that gate.

**Fix:** Drop the skip from this test, and relax its precondition from `set(MONTH_END_COLUMNS) <= set(raw.columns)` to the existing negative assertion (`not (set(MONTH_END_COLUMNS) & set(rebuilt.columns))`). Keep `_require_month_end_columns` only in the tests that read the month-end values: `test_coverage_of_the_month_end_columns` and `TestTrackedPnlSeries`.

## Info

### IN-01: A diagnostic line can still crash or stall every CLI

**File:** `src/trading_crab_lib/platform/code_version.py:22-25`

**Issue:** Two problems:

- **Crash.** Only `FileNotFoundError` and `TimeoutExpired` are caught. Any other `OSError` from `subprocess.run` propagates out of `main()` before the CLI does its work, for example a `PermissionError` when git is not executable or `_HERE` is unreadable. A `UnicodeDecodeError` while decoding git's output does the same. That includes `weekly.main`.
- **Stall.** The four sequential calls can each wait 10 s, so a slow repository (network filesystem, fsmonitor stall) adds up to 40 s to every CLI start and to the end of every pytest run.

**Fix:** Catch `(OSError, subprocess.SubprocessError, UnicodeDecodeError)`. Use one budget, either a smaller per-call timeout (2-3 s) or a single `git status --porcelain=v2 --branch` call, which reports branch, HEAD and dirty state in one process.

### IN-02: The dirty flag has false positives (submodules) and false negatives (new untracked modules), and status can contend for `index.lock`

**File:** `src/trading_crab_lib/platform/code_version.py:40`

**Issue:** The flag is wrong in two directions, and the status call can interfere with other git commands:

- **False positive.** The repo has three submodules (`gsd-scratch-work`, `trading-crab-lib`, `trading-crab`). Once they are initialised, a submodule at a different commit than recorded (for example after `git pull` without `submodule update`) makes `status --porcelain` print ` M trading-crab-lib`. The line then claims uncommitted changes although no platform code changed.
- **False negative.** `--untracked-files=no` hides a new, not-yet-added `.py` module that the running code imports.
- **Lock contention.** Plain `git status` may take `index.lock` to refresh the index, so a concurrent commit in another terminal can fail with "index.lock exists".

**Fix:** Use `git --no-optional-locks status --porcelain --ignore-submodules=all --untracked-files=no -- src scripts`, or document the scope in the docstring.

### IN-03: pytest_terminal_summary can turn a failed run into an INTERNALERROR

**File:** `tests/conftest.py:29-33`

**Issue:** The import and the call are unguarded. If `trading_crab_lib` cannot be imported, for example when pytest is run with a different `-c` or rootdir so that `pythonpath = ["src"]` is not applied and the package is not installed, the summary hook raises. Pytest then ends with an INTERNALERROR traceback after the real collection errors, and the exit code changes to 3.

**Fix:** `try: from ... import code_version except ImportError as exc: terminalreporter.write_line(f"Code: unknown ({exc})"); return`.

### IN-04: "Every platform CLI prints the code line" is not true for three data-writing scripts

**File:** `scripts/migrate_publication_lags.py`, `scripts/recompute_monthly_features.py`, `scripts/platform_snapshot.py` (each `main()`)

**Issue:** 08.5-03-SUMMARY says "every platform CLI and pytest print `Code: …` (G-16)". These three scripts rewrite or restore `data/checkpoints/platform` and print nothing. Running the wrong checkout against the data is the scenario G-16 was created for, and these scripts write to that data.

**Fix:** Add `print(code_version())` after `parse_args` in each, or narrow the claim in DECISIONS G-16.

### IN-05: Stale "tracked outputs" wording, and the scoreboard's registry read-only invariant is no longer tested

**File:** `src/trading_crab_lib/platform/report/scoreboard.py:4`; `tests/unit/test_platform_scoreboard.py:4, 12-14`

**Issue:** Two related gaps:

- **Stale wording.** The module docstrings still describe "the LAST BUDGETED RUN's tracked outputs". The scoreboard test docstring also still describes the retired tracked test, which "checks the registry is byte-identical afterwards".
- **Untested invariant.** That byte-identical check was the only test that the scoreboard never writes to the registry. The synthetic tests never compare registry bytes before and after.

**Fix:** Update both docstrings. In one synthetic `TestScoreboardTable` test, hash `world["registry"]` before and after `scoreboard_table(...)`.

### IN-06: The new live-ledger test re-derives total_trial_count's own formula, and malformed rows produce a KeyError instead of a failure message

**File:** `tests/unit/test_platform_honesty_registry.py:160-174`

**Issue:** Two weaknesses:

- **Self-confirming.** `expected = sum(prior_genuine_trials over headers) + (rows - headers)` restates the implementation, so a shared misunderstanding passes.
- **Opaque error.** `rows[0]["config"]["record_type"]` raises a `KeyError` (a test error with no message) when row 0 is an ordinary trial row. That is the exact regression the test is meant to report.

**Fix:** Use `rows[0].get("config", {}).get("record_type")` in the assertion. Also pin the epoch's literal facts, `total_trial_count() == 0 + (len(rows) - 1)` while the D-03 header carries `prior_genuine_trials: 0`, alongside the formula.
