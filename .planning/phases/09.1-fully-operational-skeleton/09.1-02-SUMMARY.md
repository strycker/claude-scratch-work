### Auto-fixed issues

**2. [Rule 2 - Correctness] `build()` honours `data.end_date`; lags are validated before any request; negative lags refused**
- **Found during:** Task 1. The config already carried `data.end_date: null # null means today`, but nothing read it,
  so setting it would have been silently ignored (LEARNINGS 13). A missing or negative lag would otherwise surface only
  after all eight fetches, and as a bare `ValueError` the CLI does not catch.
- **Fix:** `today` defaults to `data.end_date`, else today (one expression; the config comment now says "the run
  date"). `_check_lags` raises `ConfigError` (a `ValueError`, so the plan's test still matches) for an unlisted or
  negative lag; `build` calls it before the key check and before any request. `config/platform_settings.yaml` is outside
  the plan's file list (one comment line changed).
- **Commit:** `c0ccc1d`

**3. [Rule 1 - Test gap] The truncation test samples every 7th month from the first month, not from 2006**
- **Found during:** Task 2's mutation check: a `bfill` look-ahead only touches the warm-up rows (1993), which a
  2006+ sample never sees.
- **Fix:** sample `raw.index[::7]` (a superset of the plan's sample) and assert every feature is non-NaN at the 2006+
  sample months, so the comparison is on real values. The `bfill` mutation now turns it red.
- **Commit:** `f63ee7a`

**4. [Rule 3 - Blocking] `test_config_paths.py` changed for the autouse `fake_keys`**
- The plan-01 test asserted that keys are `None` with nothing exported; with the autouse fake keys it now deletes them
  first. As a side effect, a key that `load_dotenv` sets during that test no longer leaks into later tests, because
  monkeypatch now records and restores it. Commits `fd58381` and `adee702`.
