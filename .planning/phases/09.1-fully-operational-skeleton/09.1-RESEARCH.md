## Summary

The target repo is a nearly empty legacy shell (77 tracked files; the "library" is 8 tiny stub modules, the app CLI raises `NotImplementedError`). Almost everything is a deletion; the new code is about 600 lines. The research found one defect that would have shipped silently: **the target's library `pyproject.toml` builds an empty wheel.** `[tool.setuptools.packages.find] where = [".."]` discovers nothing from inside `src/trading_crab_lib/`. I reproduced it on a scratch copy: `python -m build src/trading_crab_lib` exits 0 and the wheel holds only `dist-info` files (RECORD, top_level.txt of 1 byte). Building the wheel directly produces a nested `trading_crab_lib/trading_crab_lib/...` layout instead. The reference repo already hit this (PyPI 0.1.0-0.1.4 shipped empty) and fixed it with `package-dir = {"trading_crab_lib" = "."}` plus an enumerated `packages` list. I verified that fix builds a correct sdist and wheel, and that both a wheel install and an editable install import `trading_crab_lib.platform.*` from outside the checkout. Success criterion 2 ("both packages build") passes on exit code alone, so the plan must add an install-and-import wheel smoke to CI, or criterion 2 is meaningless.

The skeleton is one walking path: `tradingcrab build` (FRED monthly series + Tiingo daily adjusted closes resampled to complete month-ends, publication lags applied once from config, 2021+ holdout physically carved, fails loud before writing anything) then `tradingcrab weekly` (5 causal features shown as a backdrop, inverse-vol weights scaled to a 10% vol target with the remainder in cash, markdown page with as-of date and code line). Both CLIs print the code line first (G-16). I prototyped the core functions (FRED month-end conversion, Tiingo month-end resample, lags, features, weights) and ran them on pandas 2.3.3 and pandas 3.0.6 with `FutureWarning` promoted to an error: all pass. The CI matrix gives pandas 2 and 3 coverage for free, because Python 3.10 resolves pandas 2.3.3 and Python 3.13 resolves pandas 3.0.6 (checked with `pip download --python-version`).

**Recommendations on the open design questions:** skip the backtest in 9.1 (option a). It is the only part of the skeleton that would evaluate a configuration, which the honesty rules say needs a registry row, and the registry does not exist yet. Ship a truncation (causal-invariance) test instead; it proves the walk-forward in 9.4 is possible without producing a performance number. Carry the `realdata` marker with one small test file now (the guide's lesson 4 says a real-data to page smoke must exist from the first milestone). Carry DECISIONS.md trimmed to live rows with stable IDs, not verbatim. Split into three plans: (1) reset + rules + M0 + CI with a constant-content tracer, (2) real build + holdout fence + features, (3) allocation + page + notebook + pointer README + Mac gate.

**Primary recommendation:** Write the library as 9 flat modules in one package `trading_crab_lib.platform` (about 600 lines total), fix the library `pyproject.toml` first (Plan 1) and prove it with a wheel install-and-import step in CI, and treat Glenn's Mac run (`tradingcrab build`, `tradingcrab weekly`, the notebook, the sign-off) as the only real-data gate, because the executor session holds no FRED or Tiingo key.

### Pattern 1: lazy paths, cwd-walk root
**What:** `root()` returns `$TC_ROOT_DIR` if set, else the nearest ancestor of the current directory containing `config/platform_settings.yaml`; else raise with the fix. `data_dir()` and friends call `root()` each time.
**When to use:** always. The reference resolved paths at import time from `__file__` (`ROOT = Path(__file__).parent.parent.parent`), which breaks for a wheel installed in site-packages and forced its `conftest.py` to scrub `TC_*` variables before import (the 08.4 UAT incident). Lazy functions let each test set `TC_ROOT_DIR` to `tmp_path`.
**Example:** see Code Examples.

### Pattern 2: fail-loud build, no partial writes
**What:** each fetch returns data or raises a `SourceError(name, reason)`; `build()` runs all fetches, collects every failure, raises one `BuildFailed` listing them all, and only then writes. Missing `FRED_API_KEY` or `TIINGO_API_KEY` raises before the first request.
**Why:** DECISIONS D-08 (a failed fetch silently produced a −98.07% gold return) and legacy P23/P26. `--allow-missing` is **omitted** in the skeleton: both sources work on the VPN, and the allocation cannot run if one of the five classes is absent, so the flag would only let a build succeed that `weekly` must then reject. It returns in 9.2 with the sources that actually get blocked (macrotrends, Yahoo). This deviates from CONTEXT's "keep its shape" note (which is guidance, not a locked decision); record it as a DECISIONS row.

### Pattern 3: publication lags applied once, completeness enforced
**What:** `apply_lags(frame, lags)` raises `ValueError` for any column without an entry; shifts with `Series.shift(L, freq="ME")` (timestamps move, so gaps are safe); the lag table is written into the checkpoint's meta sidecar and `weekly` refuses to run if the config's table differs. Skeleton table: `gs10 0, tb3ms 0, baa 0, unrate 1, SPY/TLT/IAU/USO 0`. `[VERIFIED: config/platform_settings.yaml:201]` quotes `fred_gs10:    0`, and the reference shift is `frame[c].shift(table[c], freq=freq) if table[c] else frame[c].copy()` `[VERIFIED: publication_lags.py:134]`.
**Rationale for UNRATE lag 1:** BLS releases month m on the first Friday of m+1, so it is unknown at the end of month m; the reference gives M2SL the same lag 1 (`fred_m2sl:    1`, config line 212). FRED UNRATE is revision-exposed only through annual seasonal-factor updates; record it as an accepted compromise like the reference's CAPE/M2.
**Lag-0 FRED monthly averages (GS10, TB3MS, BAA):** they are averages of daily values, fully observed by the month's close (reference ruling 4). They are model inputs only, which E-08 allows.

### Pattern 4: holdout fence by directory
**What:** `save(df, name)` writes rows ≤ `holdout.cutoff` to `data/checkpoints/` and later rows to `data/holdout/`. `load(name)` returns dev rows only; `load(name, include_holdout=True)` concatenates. A grep test asserts the string `include_holdout=True` appears only in `platform/report.py` (and tests). H-02: the fence is on fitting, not looking; the weekly page is live scoring and may read everything.
**Config value:** `holdout: cutoff: "2020-12-31"` `[VERIFIED: config/platform_settings.yaml:456]` — the date is quoted so YAML does not load it as a `date`.

### Anti-Patterns to Avoid
- **Discovery glob in the library pyproject** (`where = [".."]`): ships an empty wheel. Use `package-dir` + an enumerated `packages` list, and a hygiene test that every directory with `__init__.py` is listed.
- **Import-time path constants and `ROOT` from `__file__`:** breaks wheel installs and test isolation.
- **Merge-on-save:** D-08 root cause. Every save overwrites the whole checkpoint.
- **Fallback source = silent success:** if a source is missing the build fails; nothing falls back.
- **Centred or negative-shift operations** (`rolling(center=True)`, `shift(-k)`, `bfill`) in features.
- **A `--synthetic` flag in production code** to make the tracer run: tests monkeypatch the fetch functions instead.
- **Copying reference files:** rewrite from the architecture (G-19); use the reference for behaviour (Tiingo header, FRED quirks, lag semantics).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Month-end resampling | manual date arithmetic | `Series.resample("ME").last()`; `index.to_period("M").to_timestamp("M")` | verified on pandas 2.3.3 and 3.0.6 |
| Publication lag | row-position `shift(L)` | `shift(L, freq="ME")` | timestamp-based, safe with gaps |
| Parquet I/O | CSV or JSON dumps | `DataFrame.to_parquet` / `read_parquet` (pyarrow) | CLAUDE.md convention |
| CLI | custom `sys.argv` parsing | `argparse` subparsers | stdlib; Glenn can read it |
| Secret redaction | ad-hoc string slicing | one `_redact(text, *keys)` used on every raised or logged exception text | FRED's key travels in the URL query, so `requests` exception strings contain it |
| Notebook execution in CI | kernel + `nbclient` | `exec` of the code cells | no dependency; same failure signal |
| Wheel verification | trusting `build` exit code | `scripts/check_wheels.sh` (fresh venv, `cd` away, import from site-packages) | the empty-wheel incident passes every metadata gate |
| Code line | hand-built f-string everywhere | one `code_version()` | G-16; pattern in the reference file (git run in the package's own folder) |

**Key insight:** the dangerous parts of this phase are packaging and causality, not algorithms. Every algorithm in the skeleton is under 15 lines of pandas; every real failure mode in the project's history (empty wheel, unlagged series, silent fallback, tracked pickles) is a plumbing failure.

## Naive M3/M4: allocation and page (Q5)

**LEARNINGS.md draft (mistake → rule; source in brackets; pick 30-34):**
1. Centred rolling windows in a supervised feature leaked the future → causal features only: trailing windows, no `center=True`, no `shift(-k)`; prove with a truncation test [P1, L2-04].
2. `fred_m2sl`, `fred_totalsl`, `div_yield` entered features at their reference month for 7 phases → every raw series has a `publication_lags` entry, applied once at ingestion; an unlisted column raises [D-05, guide §1.3].

## Common Pitfalls

### Pitfall 1: the library wheel is empty (verified)
**What goes wrong:** `python -m build src/trading_crab_lib` succeeds; the wheel has only `dist-info` (top_level.txt 1 byte); `import trading_crab_lib` fails after `pip install`. Built directly with `--wheel`, the layout is `trading_crab_lib/trading_crab_lib/...`.
**Why:** target `src/trading_crab_lib/pyproject.toml:81-82` quoted `where   = [".."]` and `include = ["trading_crab_lib*"]`; modern setuptools does not let discovery escape the project root.
**How to avoid:** `package-dir` + enumerated `packages`; `scripts/check_wheels.sh` in CI; hygiene test that listed packages equal directories with `__init__.py`.
**Warning signs:** wheel under ~5 KB; `unzip -l` shows no `.py`.

### Pitfall 2: `.gitignore` swallows the new `checkpoints.py`
**What goes wrong:** the target's `.gitignore` has `*checkpoint*` followed by `!src/trading_crab_lib/checkpoints.py` (lines 22-23, quoted). The new file is `src/trading_crab_lib/platform/checkpoints.py`, which the pattern ignores; it never gets committed; CI fails on import while the local run passes.
**How to avoid:** delete that pattern; ignore by path; hygiene test uses `git ls-files --error-unmatch` on every source file; before the first push run `git status --ignored` and read it.

### Pitfall 3: the kept publish workflow
`publish-pypi.yml` triggers on `release:\n    types: [published]` (lines 4-5) with `id-token: write` and `environment: pypi`. Any GitHub Release Glenn drafts publishes both packages to PyPI. Keep the file name and the `pypi` environment (the trusted-publisher record on PyPI is keyed to them `[ASSUMED]`), change nothing in 9.1, and tell Glenn not to create a Release. It has no wheel-content gate; add the smoke before the first real publish (the reference's `RELEASING.md` §8-9 describe `twine check --strict` and the smoke).

### Pitfall 4: `import platform` shadowing
`trading_crab_lib/platform/` shadows the stdlib `platform` module when the current directory is `src/trading_crab_lib/`. I reproduced it: from that directory `import platform` resolves to the package. Never run Python, pytest or notebooks with that cwd. D-03 fixes the name; the editable install is safe (checked: from `/tmp`, `platform` is the stdlib).

### Pitfall 5: pandas 3 differences (verified on 3.0.6)
Datetime resolution is `datetime64[us]`, not `[ns]`; columns and string Series are `str` dtype; Copy-on-Write (a derived Series assignment does not touch the parent; chained assignment is a no-op); a Parquet round trip drops `freq`; `freq="ME"` needs pandas ≥ 2.2; `pct_change(fill_method=None)` everywhere. Compare values not dtypes; never mutate a slice expecting the parent to change.

### Pitfall 6: FRED and Tiingo data shape
FRED monthly dates are the first of the month (convert to month-end before any shift); `value` is a string, `"."` is missing `[ASSUMED]`; the API key is a query parameter, so exception strings contain it (redact). Tiingo `date` carries a UTC timestamp (parse with `utc=True`, drop tz, normalise). The current calendar month is incomplete: drop it. `adjClose` levels change between builds; returns do not.

### Pitfall 7: negative cash by float noise
See Q5: clamp `cash` at 0.

### Pitfall 8: `load_dotenv()` finds `.env` from the library file's directory
Default `find_dotenv()` walks up from the calling file, which is wrong for a wheel install. Call `load_dotenv(root() / ".env")`; it does not override variables already set (so an exported key wins), which is the behaviour to document.

### Pitfall 9: network and secrets in tests and CI
CI has no secrets and no network access to rely on: the socket-guard fixture makes an accidental request fail loudly. Use fake keys such as `"test-key-123"` and assert the string never appears in captured output or the page.

### Pitfall 10: VPN-blocked sources
Do not add yfinance, macrotrends or Stooq, even as a fallback (a fallback is a silent failure, D-08). Tiingo free-tier quota behaviour is unconfirmed: pace requests, bound retries, and name the ticker in every error.

### Pitfall 11: the GitHub-side state
The target keeps old Actions history, the `pypi` environment and branch settings. Nothing in 9.1 changes them; if Glenn has branch protection requiring a status-check name from the old `ci.yml` (`test-and-lint (3.10)`), renaming jobs would block the merge `[ASSUMED]`. Keep the job names `test-and-lint` and `build-distributions` to avoid it.

### FRED to month-end, Tiingo to complete month-ends, lags
```python
def fred_to_month_end(obs: list[dict]) -> pd.Series:
    s = pd.Series({pd.Timestamp(o["date"]): (np.nan if o["value"] == "." else float(o["value"])) for o in obs}, dtype=float)
    s.index = s.index.to_period("M").to_timestamp("M")          # FRED dates are the 1st of the month
    return s.sort_index()

def month_end_prices(rows: list[dict], today: pd.Timestamp) -> pd.Series:
    idx = pd.to_datetime([r["date"] for r in rows], utc=True).tz_localize(None).normalize()
    daily = pd.Series([r["adjClose"] for r in rows], index=idx, dtype=float).sort_index()
    me = daily.resample("ME").last()
    return me[me.index < today.normalize()]                     # an incomplete month is not a month-end

def apply_lags(frame: pd.DataFrame, lags: dict[str, int]) -> pd.DataFrame:
    missing = [c for c in frame.columns if c not in lags]
    if missing:
        raise ValueError(f"no publication_lags entry for {missing}")
    return pd.concat({c: frame[c].shift(lags[c], freq="ME") if lags[c] else frame[c] for c in frame.columns}, axis=1)
```

### Fail-loud build skeleton
```python
class BuildFailed(RuntimeError): ...

def build(cfg: dict, *, today: pd.Timestamp | None = None) -> pd.DataFrame:
    keys = [n for n in ("FRED_API_KEY", "TIINGO_API_KEY") if not cfg["keys"].get(n)]
    if keys:
        raise BuildFailed(f"missing environment variable(s): {keys} (see .env.example)")
    frames, failures = [], []
    for name, fetch in (("FRED", fetch_fred), ("Tiingo", fetch_prices)):
        try:
            frames.append(fetch(cfg))
        except SourceError as exc:                               # collect every failure, then raise once
            failures.append(f"{exc.source}: {_redact(str(exc), *cfg['keys'].values())}")
    if failures:
        raise BuildFailed("build stopped before any write:\n  " + "\n  ".join(failures))
    return apply_lags(pd.concat(frames, axis=1), cfg["publication_lags"])
```
