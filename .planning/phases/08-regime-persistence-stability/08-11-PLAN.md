<objective>
Close G-08-1. `pytest tests/ -q` must pass on Glenn's Mac as it does on Linux. The cure must not be
a tolerance loose enough to wave through a record that does not match its curves.

Purpose: UAT test 1 (blocker). `TestCriterion7ReMeasuredIn0810::test_the_record_is_re_derivable_from_its_own_curves`
recomputes the lift and the quality tier from the committed parquet curves. It compares them to the
committed record with exact `==`. `terminal_log_wealth` is `np.log1p(r).sum()` over 588 months, and it
is not bit-portable: on Apple Silicon (NEON + macOS libm) it lands 32 ULP (relative 7.1e-15) away from
the Linux-produced record. The curve bytes are identical; the reduction is not. The same test compares
mean turnover and both DSRs with `==`, so those would fail next on macOS once `wealth_delta` is fixed.
A genuine mismatch (the band-off record against the band-on curves) differs at about 1.5e-2 relative,
twelve orders of magnitude larger.

**A trap the plan pins, measured at plan time (pytest 9.1.1).** `pytest.approx(x, rel=1e-9)` with no
`abs` still applies the DEFAULT absolute tolerance of 1e-12. Measured: `0.0 == pytest.approx(1.8e-13, rel=1e-9)`
is **True**. The committed DSRs are 1.8159919159760753e-13 (baseline) and 4.1314825526463704e-12
(joint). A rel-only approx would therefore accept a baseline DSR of 0.0. That is a check that can only
confirm, and it is the signature defect this project tallies. The comparison MUST pass `abs=0.0`, and
an arm must prove it.

Output: one comparison routine with its discrimination arms, a swept and listed defect class, and
updated recorded counts.

**Scope fences.** No record, curve or registry row is regenerated or touched: this plan changes how a
test COMPARES, not what was measured. No 2021+ holdout read. `legacy/` and the reference submodules
stay untouched. The legacy-import ratchet stays at 31.

## Honest-evidence note: how each new check can fail

| Check | Fails when |
|---|---|
| Re-derivation via `_record_mismatches` | The committed record and curves come from different runs: any field off by more than 1e-9 relative. |
| Band-off arm | The routine is loosened (for example a rel of 1e-2 or an absolute floor) so that the 07-11 record would pass against 08-10's curves. Also fails if any of the four fields stops being compared, because the arm asserts the exact four-key list, not "non-empty". |
| 1-ppm arm (7 keys x 2 suffixes) | Any single field's tolerance is widened above 1e-6, a field drops out of the comparison, or `abs=0.0` is removed (DSR keys). |
| DSR-zero arm | `abs=0.0` is removed. This is the default-floor trap, measured at plan time. |
| Absorbed-noise arm and macOS pair | The float rule reverts to exact equality, or the tolerance is tightened below about 1e-13. This arm makes the Linux suite reproduce G-08-1. |
| Flipped-boolean arm | Booleans are compared with approx or truthiness instead of identity. |
| Hurdle arm | The live hurdle comparison is loosened. |
| Recorded-count pin | Already exists (08-10). It fails if any of the four sites is not updated to the live count. |
