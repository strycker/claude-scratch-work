## Honest-evidence note: how each new check can fail

| Check | Fails when |
|---|---|
| q1-a guard | Someone implements a fallback (for example q1-c) without a ruling, and the report starts scoring an older month. |
| q1-b cold-start test | The degraded branch scores, filters, bands or saves anything, or serves anything but an empty book at 100% cash. |
| q1-b warm-hold test | The held book differs from the prior executed book, or any state checkpoint's bytes change. |
| q1-c scored-row spy | Any scored value differs from the observed `monthly_features.loc[as_of, cols]`: imputation, a forward-fill, or the wrong row. |
| q1-c month-stepping test | The belief or band steps on the latest row's month instead of the scored month (a double-count risk). |
| q2 degenerate / varying pair | The disclosure or withholding fires on the wrong side of the fact, or uses a rounded or threshold comparison. |
| Real-data sequence | The supported commands do not produce what the ruling predicts on the tracked data. The branch table is the pre-registered expectation. |
| §3 status sentence | The record claims CLOSED without a produced report: the grep plus the acceptance criterion forbid it. |
| Registry sha256 / count / `git status` | Anything in this plan wrote a registry row or touched the repo's data. |
