<objective>
Close CR-01 on the path Glenn trades from. The Bayes filter's likelihood `L_t(j) = posterior(j) /
prior(j)` must divide by the prior the nowcaster was trained and calibrated on, not by the
whole-label distribution.

**The defect, verified twice** (08-REVIEW.md CR-01; 08-VERIFICATION.md gap 1, which reproduced the
served belief exactly):

| | whole-label prior (in use) | training prior (the fit's 153 rows) |
|---|---|---|
| prior over [0..5] | {0: .058, 1: .328, 2: .102, 3: .288, 4: .121, 5: .104} | {0: .072, 3: .895, 4: .033}, classes_ [0, 3, 4] |
| state 3's L_t | .564 / .288 = **1.96**, evidence FOR | .564 / .895 = **0.63**, evidence AGAINST |
| cold-start served belief | 3: .369, 0: .272, 1: .213 | about 0: .300, 1: .293, 3: .163 |

There is a second consequence (CR-01, second paragraph). States absent from `classes_` get ratio
1.0, while present states are inflated by 1 / Σ_present(prior). So a flat posterior pushes mass
away from absent states on every step. Dividing by the training prior over `classes_` alone removes
this: a posterior equal to that prior gives 1.0 for every state, present or absent. 08-17 pins
that property in `regime_filter` and makes the old prior shape refusable.

**Decision on π_0 (asked of the planner: decide and justify).** The cold start stays
`unconditional_belief(regime_labels)` over all K states, and `A` stays
`transition_matrix_for(regime_labels)`. The reasons:
1. π_0 is a belief over the whole K-state space. The training prior lives on `classes_` only (3 of
   6 at serve). Using it as π_0 would put zero initial mass on states 1, 2 and 5 because of when
   HYG/UEC/UNG started (the feature block begins 2007-04), which is a fact about the fit's rows,
   not about the world.
2. π_0 and `A` are estimated from the same L1 labels and describe the same latent process. The
   empirical occupancy is the natural start for that `A`.
3. The likelihood prior is a different object: the class frequency the L2 posterior is calibrated
   against. Bayes: p(x | j) ∝ p(j | x) / p_train(j). Only that inversion needs the training prior.
4. The cold start enters once, and its influence decays under `A`. The likelihood prior enters
   every step.

So the rule is two roles, two rules, each stated in the code where it is used. The old "one call
for both roles" sentence is removed.

**Why the served path first (tracer).** It is the live defect: the executed book is built on the
inverted evidence. This plan wires the one rule through every layer it passes: fit → persist →
load → filter → allocation. 08-17 then points both backtest drivers at the same returned prior.
08-19 re-measures everything the change moves.

**Scope fences.**
- No recipe change: same embargo, same `_cv_safe_active_features`, same calibrated LR, same rows,
  and the posterior is bit-identical.
- No change to π_0, `A`, the band, the hysteresis or q1-c/q2-ii.
- CR-02 (state-id alignment across refits), CR-03 (publication lag), CR-04, WR-03 (atomic serving
  build) and IN-04 (`serving._training_block` re-derivation) are out of scope.
  `_training_block` stays. A test cross-checks it against the fit's own prior.
- Budget 0: no registry row; the serving fit stays `NO_REGISTRY`; no holdout read by any fit or
  any new test.
