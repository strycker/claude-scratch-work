<objective>
Answer audit item A11, and write the answer as the reversal it is.

Purpose: ROADMAP criterion 7. A11 asks whether any gate in this project should fail on a
**bad-but-working** model, rather than only on a broken measurement. Glenn left it **open by
deliberate choice** on 2026-09-18 when the band tiers were decided, and **chose to reopen it on
2026-09-21**. `08-CONTEXT.md` D-06 is explicit: *"It is answered either way and written as the
reversal of a prior decision that it is, not as a cleanup."*

Output: a ruling, a record framed as a reversal, a pin, and an ADR.

**Why it is being reopened now, concretely — this is the new fact and it belongs at the top of
the record.** On 2026-09-18 A11 was an abstract worry. On 2026-09-21 there is an instance. Read
straight out of `outputs/reports/platform/joint_lift/measurement_l1only.json`, the criterion-7
measurement over 588 steps, 1972-01-31 to 2020-12-31:

- `wealth_delta` **-0.123438** — an **11.61% terminal-wealth shortfall** against classifier #1
  alone.
- `wealth_delta_universal_ok` **True**, `wealth_delta_domain_note` **False**,
  `dd_delta_universal_ok` **True**, `dd_delta_domain_note` **False**.
- Both legs' deflated Sharpe: **2.28e-12** and **1.47e-11**, each carrying the verdict string
  *"does not clear the multiple-testing hurdle — statistically indistinguishable from a
  skill-less discovery given the number of trials searched"*, at `n_trials` 42 and
  `sharpe_variance` **1.0**, the declared placeholder.

**So: a working model lost 11.61% of terminal wealth, its deflated Sharpe was indistinguishable
from zero, and not one of the four band flags fired — not even the advisory ones.** That is A11
stated as a measurement rather than a worry, and it is the whole reason the item is back.

**The prior reasoning, quoted so the reversal has something to reverse.** `07-BANDS.md` §8 and its
framing paragraph: *"What a plausibility band is (D-07, restated). It asserts a number is
physically possible. It never asserts a number is good. Audit item A11 — that no gate in this
project can fail on a bad-but-working model, only on a broken one — stays open and conscious.
Changing that is a design-freeze decision, not a wave-2 one."* And §8's closing: promoting the
domain tier *"would mean gating on `[ASSUMED]` numbers that no measurement in this project
supports."* Both sentences remain true. The question is whether they remain **sufficient** now
that the instance exists.

**Sequencing, and it is not incidental.** This plan is in wave 1, ahead of everything that
produces a number. Plan 08-10 re-measures criterion 7 in wave 5. If A11 were answered after that
re-measurement, the gate would have been chosen with knowledge of the value it would judge — the
precise tie-break shape the pre-registration at `298b1bc` forbids elsewhere in this project. The
ruling is pre-registered by being made first.
</objective>

      <pros>
        Costs zero registry trials. Preserves D-07 exactly. Avoids gating on `[ASSUMED]` numbers,
        which is 07-BANDS §8's standing objection and it has not been refuted. Converts A11 from
        "open by deliberate choice" — a state that reads as unfinished — into "answered: no, and

        Consistent with the project's repeated position that measurement is the gate and the sign
        is not (D-06).
      </pros>
      <cons>
        The platform ships with **no** gate that can fail on a bad model. The 11.61% shortfall
        with all four flags green stands as the documented consequence, and a reader must take
        that on the chin rather than be protected from it. The reversal is real but modest: the
        item stops being open without anything behaving differently.
      </cons>
    </option>
    <option id="b-promote-dsr">
      <name>Answer YES, using the deflated Sharpe hurdle — the one candidate whose threshold is derived, not assumed.</name>
      <pros>
        `expected_max_sharpe(n_trials, sharpe_variance)` is **arithmetic on the trial count**, not
        a band written by analogy — it is the only quality threshold in this project that is
        derived. It already exists, is already computed every run, and already carries a verdict
        string. Costs zero registry trials to promote. It would gate on exactly the failure this
        project's honesty framework was built to catch: a result indistinguishable from a
        skill-less discovery given the search performed.
      </pros>
      <cons>
        **It would turn criterion 7's already-recorded MET into a FAILED, retroactively**, on both
        legs, at DSR 2.28e-12 and 1.47e-11. That consequence must be accepted knowingly, in
        advance, not discovered at plan 08-10. And the hurdle is not as derived as it looks:
        `sharpe_variance` is the **1.0 placeholder** until 20 independent Sharpe-bearing trials
        exist, so the 2.208694 hurdle rests on a declared assumption — a weaker version of
        07-BANDS §8's objection, but the same objection.
      </cons>
    </option>
    <option id="c-promote-domain-bands">
      <name>Answer YES by promoting the existing domain/advisory tier to governing.</name>
      <pros>
        Requires no new number and no new machinery: `abs(wealth_delta) >= 5` and
        `abs(dd_delta) >= 0.5` already exist as advisory notes and would simply become failures.
        Zero registry trials.
      </pros>
      <cons>
        **Measured, and decisive: it would not have fired.** On the actual result
        (`wealth_delta` -0.123438, `dd_delta` +0.024084) both domain flags are already recorded
        `False`. Promoting them buys the appearance of a quality gate with none of the substance,
        while incurring the full weight of 07-BANDS §8's objection — these are `[ASSUMED]` numbers
        that no measurement supports. Tightening them toward the observed values to make them bite
        would convert a plausibility band into a quality band fitted to a result already seen,
        which is what D-07 and ADR-0001's selection criterion refuse.
      </cons>
    </option>
    <option id="d-preregister-new">
      <name>Answer YES with a NEW pre-registered quality threshold, declared now and applied at 08-10.</name>
      <pros>
        The only option that produces a gate which both bites and is pre-registered rather than
        fitted. Being made in wave 1, before any of this phase's numbers exist, it is genuinely
        pre-registered.
      </pros>
      <cons>
        There is no measurement in this project from which to derive such a threshold, which is
        why the existing four are all `[ASSUMED]`. Calibrating one costs registry trials against
        a ceiling with **two** left. And a pre-registered number chosen from intuition is still an
        intuition — it is merely an honest one. If this option is taken, the threshold must be
        written into `08-A11.md` with the value it would reject, before 08-10 runs.
      </cons>
    </option>
  </options>
