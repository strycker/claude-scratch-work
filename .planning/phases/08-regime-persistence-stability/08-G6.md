# G6 — which consumers of `vol_targeted_tilt` pool, and which do not

Validation gap **G6** was carried out of Phase 7's wave-2 Nyquist audit unwritten, because
`backtest/driver.py` was outside that audit's write scope. It is written now.

ADR-0001 § RE-PIN 2026-09-18's recurrence exemption admitted classifier #1's crisis state below
design §4.4 criterion 1's ~8% occupancy floor, **conditionally**. Condition (iv):

> every downstream statistic computed on it carries an explicit low-n flag, and it is *not* used
> for unshrunk point estimates — no per-regime Sharpe, no per-regime covariance — without partial
> pooling toward the all-history model (design §6.1 mitigation 2).

`allocation/joint_tilt.py::pool_low_n_regime_sharpe` implements the Sharpe half of that. Two of
the three call sites that feed `vol_targeted_tilt` do not call it.

## 2. Why this is written as a pin of the NON-compliance

The obvious way to write G6 — *"assert the driver's tilt receives a condition-(iv)-compliant
frame"* — is **a test that can only pass**. It fails today for the right reason, gets marked
`xfail` or quietly deleted, and tells a future reader nothing about what the code does.
`.planning/UAT-AUDIT-2026-09-09.md` § 4 names the class: evidence of *existence*, *shape*,
*pure-function correctness* or *placement*, none of which "can detect a physically impossible
value". This project has six recorded instances, the sixth authored while scoping this very phase
(`08-CONTEXT.md` AMENDMENT 2026-09-21). G6 written the compliant way round would have been the
seventh.

So the pin records the code as it is. The day someone makes a consumer pool, the arm goes red and
the change has to be conscious. That visibility is the entire point of an open audit item.

### The both-halves rule, and why one half is worthless

`pool_low_n_regime_sharpe`'s own docstring:

> Regimes at or above the floor are returned unchanged, so this is a **strict no-op** for a
> labeling that satisfies §4.4 criterion 1 without the exemption.

Therefore *"the observed frame equals the unpooled table"* is **also true of a pooled
implementation**, on any fixture whose regimes all meet the floor. Half 1 alone is the same defect
in a new costume. Every arm accordingly:

1. **asserts its precondition first** — `low_n_regime_flags(unpooled)["low_n"].any()` — so a
   fixture that stops containing a sub-floor regime fails *on the precondition*, not vacuously on
   the pin;
2. **asserts both halves** — equal to the unpooled table **and** different from
   `pool_low_n_regime_sharpe`'s output, with a differing `(regime, asset)` cell named in the
   assertion message.

The fixtures, measured:

| arm | sub-floor regime occupancy | cell pooling moves | unpooled → pooled |
|---|---|---|---|
| driver | 3/51 = **5.8824 %** (credibility 0.7353) | `(2, SPY)` | −4.984659 → −3.764478 (Δ −1.220180) |
| | | `(2, TLT)` | +15.014234 → +11.376312 (Δ +3.637922) |
| weekly / contrast | 14/234 = **5.9829 %** (credibility 0.7479) | `(2, SPY)` | +0.043301 → +0.214833 |
| | | `(2, TLT)` | +3.464102 → +2.693807 |

The contrast arm needed a second correction found during execution and worth recording, because it
is the same trap one level down: the sub-floor regime must carry **two** positive-Sharpe assets.
With one, `_per_regime_tilt` clips the negative to zero and normalizes the survivor to 1.0 either
way — pooling moves the Sharpes and **not the weights**, and the arm passes on a tautology. With
two, pooling changes their ratio and the portfolio moves by **1.2303 percentage points** (SPY
0.657673 → 0.669976, TLT 0.342327 → 0.330024). All three arms were mutation-checked: feeding the
pooled frame to the pin fails half 1; a flat-occupancy fixture fails the precondition; forcing
`joint_tilt` not to pool (via an all-above-floor `occupancy_1`/`occupancy_2`) makes the contrast
arm's deltas exactly `{SPY: 0.0, TLT: 0.0}` and fails it.

## 3. What G6 deliberately does NOT pin

- **Condition (iv)'s covariance clause.** The condition forbids an unshrunk per-regime
  *covariance* as well as an unshrunk per-regime Sharpe. That half is **out of scope for Phase 8**
  (`08-CONTEXT.md` scope fences) and is not an oversight: **no per-regime covariance exists at
  L4-01**. `tilt.py::portfolio_vol` is a linear-sum/EWMA estimate over the blended weight vector,
  explicitly marked `ponytail` in its own source, and the clause falls to L3 — design §6.2,
  regime-conditional Ledoit–Wolf. There is nothing to pin until L3 exists. 07-10's summary already
  recorded this as known gap 1; G6 does not close it and does not claim to.
- **Whether the non-compliance is *wrong*.** The pin says what the code does. Whether
  `driver.py` and `weekly.py` *should* pool is an open design question — pooling changes the
  allocation, and the argument for and against is about estimation risk versus the honesty of
  reporting a crisis state's own measured Sharpe. A test cannot settle that and this one does not
  try.
- **Any 2021+ behaviour.** The arms are synthetic-only: no network, no real checkpoints, no real
  trial registry. Nothing here reads the locked holdout.

## 4. What a red result means

**Someone made a consumer compliant. Move the pin deliberately — do not delete it, and do not
"fix" the test.**

Concretely: pooling a sub-floor regime's Sharpe changes the tilt, therefore the allocation weights,
therefore ROADMAP **criterion 7**'s measured lift — a number Phase 8 re-measures for an entirely
different reason (the labeling change). If the pin goes red, criterion 7's previously recorded
values are no longer comparable to the post-change ones, and the commit that turned it red must say
so. **Fixing G6 is not authorised by this phase.** A comment to that effect sits at the pin itself,
in `_assert_unpooled_not_pooled`, so a reader who never opens this file still sees it.
