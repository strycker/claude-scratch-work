<objective>
Make §5.3's anti-flicker machinery gate allocation, and close audit item A7 — with the
mechanism and the thresholds decided by Glenn, priced in registry trials, before anything is
written.

Purpose: ROADMAP criterion 4. `allocation/hysteresis.py::update_active_regime` is imported by
`backtest/driver.py:67`, `backtest/joint_driver.py:97` and `report/weekly.py:41`. It computes
`active_regime` — and per audit item **A7** (rated High, open since 2026-09-09) that value gates
nothing: weights come from `vol_targeted_tilt(regime_probs, ...)`. A7: *"Decide Phase 4 C3: wire
hysteresis into allocation, or reword the criterion. Today the thresholds stabilize a label, not
a portfolio."* Leaving it inert is not an option.

Output: the mechanism, at all three call sites, plus the A7 closure record.

**A7 is true, and F-2 shows something harder.** Under `ROUTING_L1_ONLY` — the decision-bearing
routing — the input to `update_active_regime` is `_last_state_one_hot(states_1)`. With a one-hot
input and `0 < unwind_threshold <= act_threshold <= 1.0`, branch 2 fires iff `prev_active ==
argmax` and otherwise branch 3 selects the single state at p=1.0. The function is therefore **the
identity on argmax, for every threshold pair the config can hold**. Measured on the tracked curve
and re-derived at plan time: `active_regime` is elementwise equal to `state_1` in all **588**
months, changes **246** times, and is `None` **zero** times.

Under `l2`, where real calibrated probabilities reach it: `active_regime` changes **462 / 587 =
78.7%**, is `None` in **387 / 588 = 65.8%** of months, and **100** steps are degraded. The
anti-flicker state machine, fed genuine probabilities, **flickers nearly twice as much as the raw
label it was meant to stabilise**, by oscillating in and out of neutral.

**What that means for each mechanism, computed rather than argued — and it is the decisive input
to Glenn's choice.** `vol_targeted_tilt` already computes `regime = probs.idxmax()` internally at
`tilt.py:190`, and `regime_tilt_weights` on a one-hot reduces to `_per_regime_tilt(regime)`
because `_per_regime_tilt` already normalizes to sum 1. So on the decision-bearing leg:

| mechanism | effect on the **decision-bearing** l1only leg | registry cost |
|---|---|---|
| **(a) hard gate on `active_regime`** | **none.** `active_regime` is already the argmax and p=1.0 always clears any admissible `act_threshold`, so the tilt receives the same regime it receives today. | 0 |
| **(b) bounded-turnover weight path** | **changes it.** The bound applies to `w_t - w_{t-1}` regardless of the probability vector's shape. Mean monthly turnover today is **0.119788** (joint, l1only) and **0.163251** (baseline, l1only). | **2 rows, 42 -> 44 — the ADR-0002 ceiling exactly, leaving zero headroom for the rest of v1.** |
| **(c) hysteresis scales the tilt's magnitude** | **none.** p=1.0 always clears the act threshold, so the shrink factor is 1.0 at every step. | 0 |

Each of those is a prediction and each is measured in this plan before the decision is acted on.
The corollary is uncomfortable and belongs in front of Glenn rather than in a footnote: **two of
the three mechanisms close A7 without changing a single decision-bearing number**, because the
decision-bearing routing's probability vector is degenerate. That is not an argument against them
— it is the corrected causal model — but it must be known when choosing.

**Ordering, and why §5.1 came first.** §5.3 cannot be *evaluated* until the probability vector it
consumes stops being degenerate. That is D-04's ordering decision and F-2 gives it a stronger
reason than D-04 itself did.

**Task 1(ii) — `hyst-input-per-classifier`, the mismatch DECLARED.** The hysteresis stays on each
classifier's own belief; that the book trades a blend of both is written down as out of the
state machine's remit. A "blended belief" is not defined: classifier #1 has K=6 and #2 K=5, with
independent state ids, so there is no common vector to blend. The proper resolution is a joint
R1 x R2 state space (Glenn's earlier proposal) — recorded as future work, not done here.

**tau — a 5-percentage-point no-trade band, NOT SWEPT.** Source: the absolute half of a common
practitioner rebalancing convention (the "5/25" drift band) — taken from outside this backtest and
**not** chosen by reading its turnover, so it is not fitted to the result. Semantics, fixed here so
that no edge case is decided after seeing a number:
  - Per **risky** asset `a` at step t: if `|target_a,t - held_a,t-1| <= 0.05`, hold `held_a,t-1`;
    otherwise trade to `target_a,t`. `held` is the last **executed** weight, not a drifted one.
  - The comparison is `<=`, so a move of exactly 5pp is **not** traded.
  - **Cash is the residual**, `1 - sum(risky)`, and is never itself subject to the band.
  - If the residual would be **negative**, the assets being traded this step are scaled down pro
    rata until the book sums to 1; held assets are not touched. Test this branch explicitly.
  - An asset absent from the target (a zero target) is traded to zero only if its held weight
    exceeds 0.05.
  - The **first** step has no `held` and trades to target in full.
  - Identical at all three call sites — `driver.py`, `joint_driver.py`, `report/weekly.py`.

**Task 2 — `keep-absolute`: act 0.70 / unwind 0.40 for both K=6 and K=5.** The plan's own test for
this option — "if the filtered belief routinely exceeds 0.70, the original values were right" — is
met: after the filter the belief clears 0.70 in **307 of 488** non-degraded months for #1 and
**415 of 488** for #2 (08-CHURN.md §8). It is also the only choice not made with that distribution

K=6 and 3.5x at K=5; a K-relative rule is named as the path to adopt, under a rule stated before
any value is read, **before** L2 ever becomes decision-bearing. The invariant
`0 < 0.40 <= 0.70 <= 1.0` holds, so Task 3's one-hot identity proof stands.
