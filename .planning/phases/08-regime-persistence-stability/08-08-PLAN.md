<objective>
Wire the Bayes filter into the two drivers and the weekly report, then measure what it did — with
the control that makes the measurement attributable.

Purpose: ROADMAP criteria 1 and 2. Plan 08-06 built the filter and its guard; this plan puts it in
the loop and produces Track B's first number. `driver.py:472-476` and
`joint_driver.py:411,449,455` call the refits once per step; the loop owns step-to-step state and
the model is stateless per step, so the recursion is a **loop variable**, not a feature.

Output: the wiring, the belief artifacts, and `08-CHURN.md`.

**The structural fact this plan must state out loud rather than let UAT discover.** Under the
**decision-bearing** `ROUTING_L1_ONLY` (ADR-0002 decision (e)), `_refit_l2` is never called and
`probs_1 = _last_state_one_hot(states_1)` — a one-hot on the jump model's terminal-month label.
**The filter therefore changes nothing on the decision-bearing leg, by construction.** Everything
§5.1 does is visible only on the `l2` routing, which is **observational and firewalled**: nothing
downstream may change on the basis of the L2 leg. That is not a disappointment to be discovered at
verification; it is the corrected causal model from `08-CONTEXT.md`'s AMENDMENT, and this plan
**pins** it — the l1only curve must reproduce bit-for-bit, and if it does not, something touched
L1 that was not supposed to and that is a bug, not a result (S-4).

**Why the filter is not applied to the one-hot.** A one-hot on a label is not a likelihood. Running
`filter_step` on it would produce a smooth belief where the routing declares there is none, would
change the decision-bearing leg for a reason that is an artefact of the wiring rather than a model
improvement, and would destroy the only clean before/after comparison this phase has. The decision
is recorded in the module docstring, not just in a test.

**Three numbers, because two can masquerade and one cannot be attributed.**

| | what it is | expected |
|---|---|---|
| **A** | `state_1` changes / 587 | **246, unchanged.** L1 is untouched. |
| **B0** | argmax of the **raw** posterior (`joint_lift_probs_1_l2.parquet`) | **unchanged.** The nowcaster is untouched; only what is done with its output changes. |
| **B1** | argmax of the **filtered belief** (`joint_lift_belief_1_l2.parquet`) | the new number. **No target is pre-declared.** |

B0's invariance is the control. Without it, a movement in B1 could equally be a nowcaster change,
and the phase would be back to attributing a number to a cause it never checked — which is the
defect that produced this phase's own AMENDMENT.

**No target is pre-declared for either churn metric.** `08-CONTEXT.md` is explicit. B1 going up is
a valid honest result and is reported as one. The roadmap note is equally explicit that this must
not be addressed by smoothing the reported number, since §5.4 says to report that quantity
prominently.
</objective>
