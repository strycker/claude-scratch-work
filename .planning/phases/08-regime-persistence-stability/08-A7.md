## 2. Which of A7's two options was taken, by whom, and when

**The criterion is reworded.** Allocation does **not** act on `active_regime`, which still
gates no weight. Glenn decided this on **2026-09-24**, after plan 08-08 (wave 3) had finished,
with its measurements in view (`08-CHURN.md`). The ruling is recorded verbatim in
`08-09-PLAN.md` under `<rulings>`, commit `36bbf28`. A7 lists rewording as one of its two
options, and it was chosen knowingly.

What makes the rewording more than a relabel is the mechanism that came with it. Design §5.3
reads *"hysteresis bands (act when P crosses ~0.7; unwind below ~0.4) **and/or** smoothed
allocation response with bounded turnover"*. Glenn chose the **bounded-turnover** arm (option
`b-bounded-turnover`): a no-trade band on the executed book. A7's complaint was *"stabilize a
label, not a portfolio"*. The band stabilizes the portfolio directly, and the label stays a
label.

**The reworded Phase 4 criterion 3.** This is proposed text for ROADMAP. This plan does not edit
ROADMAP.

> A naive vol-targeted regime-tilt allocation is produced, and its **executed book moves only
> where the target moves by more than a 5-percentage-point no-trade band** (design §5.3,
> bounded turnover), so the mix does not flip on every small change. The act ~0.7 / unwind ~0.4
> hysteresis produces a **reported** active-regime label, which gates no weight.

The purpose clause is now testable, and this plan tests it. On the synthetic fixtures, the band
lowers summed turnover at `driver.py` and at `joint_driver.py`. Both drops are asserted, not
assumed. The observational l2 readings are in `08-09-SUMMARY.md`. The decision-bearing reading
belongs to 08-10.

## 3. F-2's identity: measured, and pinned

**Under the decision-bearing routing the hysteresis stabilizes nothing.** Under
`ROUTING_L1_ONLY` the input to `update_active_regime` is `_last_state_one_hot(states_1)`.
Suppose the input is one-hot and `0 < unwind <= act <= 1.0`. Branch 2 fires exactly when
`prev_active` is the hot state. Otherwise branch 3 picks the single state at p = 1.0, which
clears any admissible act threshold. The function is therefore the **identity** on argmax.

The same identity, measured on the tracked curves:

| curve | window | `active_regime == state_1` | changes | `None` | degraded |
|---|---|---|---|---|---|
| `joint_lift_baseline_l1only.parquet` | 588 steps, 1972-01-31 → 2020-12-31 | **588 / 588** | **246** | **0** | 0 |
| `joint_lift_joint_l1only.parquet` | same 588 steps | **588 / 588** | **246** | **0** | 0 |

Both files were last written at `d5c3ac9`. They are byte-identical to the band-off re-run in §8.

**The pin.** `tests/unit/test_platform_hysteresis.py::TestOneHotIdentity` covers:
- 36 admissible `(act, unwind)` pairs, including `(1.0, 1.0)`, `(1e-9, 1e-9)` and the ruled
  `(0.70, 0.40)`;
- for each pair, K ∈ {5, 6}, every hot state, the cold start, and every possible
  `prev_active`, which is 72 cases per pair.

Two arms show that it can fail:
- a real posterior `{0: 0.55, 1: 0.45}` with `prev_active = 1` returns 1 and not the argmax;
- `act = 1.01` returns `None` on a cold start.

Mutating the cold-start `>=` to `>` turns 8 grid cases red. This pin landed first, in `2f8eece`,
before any mechanism was written.

## 4. Is the chosen mechanism inert on the decision-bearing leg? No, and deliberately so

The other two options would have been inert there. Under **(a) hard gate**, `active_regime`
already *is* the argmax on l1only, so the tilt would get the same regime it gets today. Under
**(c) magnitude scaling**, p = 1.0 clears any admissible act threshold, so the shrink factor is
1.0 at every l1only step. **Both (a) and (c) would have closed A7 without changing one
decision-bearing number.**

**(b) is not inert.** It bounds `w_t − w_{t−1}` whatever shape the probability vector has, so
**the l1only curve differs from the tracked one once the band is on**. That is the reason it
costs 2 registry rows. This plan did **not** run the decision-bearing leg with the band on.
Criterion 7's re-measurement belongs to 08-10.

What this plan does guarantee is that any movement 08-10 measures can be attributed to the band
alone:
- **Real data.** With the band disabled, `scripts/run_joint_lift.py --routing l1` was run as a
  NO_REGISTRY dry run. The re-run is `cmp`-identical to `git show 36bbf28:` for
  `joint_lift_{baseline,joint}_l1only.parquet` and `joint_lift_probs_{1,2}_l1only.parquet`,
  and `assert_frame_equal` passes exactly. Criterion 7 reproduces: `wealth_delta`
  **−0.12343826162064975**, `dd_delta` **+0.02408401236666291**, 588 steps,
  1972-01-31 → 2020-12-31. The registry read 42 before and 42 after.
- **Unit.** `TestNoTradeBand::test_band_off_l1only_curve_is_the_pre_0809_curve_bit_for_bit`
  compares the band-off l1only joint curve to a sha256 generated at `36bbf28`, before any
  08-09 change. It passes with the key absent and with it set to null. The same class shows
  that the band **on** moves the curve.

## 5. The third inconsistency: one classifier in the machine, two in the book

`joint_driver.py` hands `update_active_regime` **classifier #1's belief alone**, while
`blend_regime_tilts` trades **both** classifiers. The state machine and the portfolio therefore
disagree about which regime the book is in.

**Glenn's ruling (Task 1(ii), `hyst-input-per-classifier`): the mismatch is DECLARED out of the
state machine's remit.** A "blended belief" is not defined. Classifier #1 has K = 6 and
classifier #2 has K = 5, and their state ids are independent, so no common vector exists to
blend. The proper fix is a joint R1 × R2 state space, which was Glenn's earlier proposal. It is
recorded as **future work** and is not done here. The declaration now lives in
`joint_driver.py`'s module docstring, replacing the note that left it for this plan. Under
option (b), the mismatch has no effect on the weights, because `active_regime` gates none of
them.

## 7. The free parameter: τ = 5 percentage points, **not swept**

| | |
|---|---|
| value | **0.05** (`allocation.no_trade_band`) |
| reason | the absolute half of the practitioner "5/25" rebalancing drift band. It was taken from **outside** this backtest and **not** chosen by reading its turnover, so it is not fitted to the result |
| sweep | **not swept**. No other value was evaluated on any leg, and a sweep would be an unregistered selection dimension |

The semantics are Glenn's, fixed before any number existed. `allocation/hysteresis.py::execute_rebalance`
implements them once, and all three call sites use it (§9):
- **The band.** For each risky asset, if `|target − held| <= 0.05`, hold `held`. Otherwise
  trade to target. `held` is the last **executed** weight, not a drifted one.
- **The boundary.** A move of exactly 5pp is **not** traded. The comparison is plain
  floating point with no tolerance.
- **Cash** is the residual `1 − Σ risky` and is never itself banded.
- **Negative residual.** If the residual would be negative, **only the assets traded this step**
  are scaled down pro rata. Held assets are untouched.
- **A zero target** is sold to zero only if the held weight exceeds 0.05.
- **The first step** has no `held` and trades to target in full.

**Two readings this plan had to take, stated rather than absorbed.** Both were fixed before any
real-data number was read, and neither touches a decision-bearing number.
1. **Leading degraded steps.** A degraded step executes nothing: it holds the previous book,
   and at the start there is no previous book. So the first *non-degraded* step is "the first
   step" and trades in full. This matters only where steps degrade. The l1only leg has 0
   degraded steps, so it is unaffected. l2 has 100.
2. **Weekly cadence.** One band step is one **month**, the same rule the 08-08 belief uses. A
   same-month weekly re-run re-bands this month's target against the **same** held book the
   first run used, which is the previous month's execution. It does not band against its own
   output, which in the negative-residual case would compound. Held books persist in the
   `executed_weights` checkpoint, loaded before they are saved.

If Glenn reads either one differently, each is a one-line change at a single site.

## 8. The thresholds: 0.70 / 0.40 kept, for K = 6 and K = 5

This is Task 2, ruled `keep-absolute`. **act 0.70 / unwind 0.40 for both classifiers. No
coefficient and no registry trial.**
- **The option's own test is met.** After the Bayes filter, the belief clears 0.70 in **307 of
  488** non-degraded months for #1 and **415 of 488** for #2 (08-CHURN.md).
- **It was the only option not chosen with that distribution in view.**
- **Recorded, not resolved.** 0.70 is 4.2× uniform at K = 6 and 3.5× at K = 5. The named path
  is a K-relative rule. It must be stated before any value is read, and adopted **before L2
  becomes decision-bearing**.

The invariant `0 < 0.40 <= 0.70 <= 1.0` holds, so the identity in §3 stands. The invariant is
now checked when the config is read: `hysteresis_thresholds()` raises if a value drifts, and
there is no silent fallback. A test pins the live config at `(0.70, 0.40)`.

## 9. The three call sites changed together

A7 came about because three sites diverged. All three now call one helper:
- `backtest/driver.py`, including the `use_regime_tilt=False` ablation, which runs the same
  allocation code;
- `backtest/joint_driver.py`;
- `report/weekly.py`.

`test_all_three_call_sites_resolve_the_one_band_helper` asserts that each module's
`execute_rebalance`, `no_trade_band_from_config` and `hysteresis_thresholds` is the
`allocation/hysteresis.py` object, checked by resolved object and not by grep.

**Behaviour arms at every site.** Each exhibits:
- a suppressed trade **and** an allowed trade;
- `held` threaded as the previous executed book;
- a band-off path that passes the target through unchanged.

Each is paired with a mutation that fails it. Ignoring the executed book fails at `driver.py`,
at `joint_driver.py` and at `weekly.py`. Never threading `held` fails at `driver.py`.
Re-banding a same-month re-run against its own output fails at `weekly.py`.

**The negative-residual branch** is exercised three ways:
- in the unit arm, where held 0.64 plus traded 0.40 is 1.04 and the traded assets scale by
  0.9;
- at serve, where held SPY 0.32 plus TLT's 0.715 target scales TLT to 0.68;
- inside a synthetic joint-driver run, in 1 of 60 steps.

`tests/unit/test_platform_pooling_consumers.py` (the G6 pin, T-08-55) is **unmodified**. Its
last change is still `94d5283`, and it passes.

## 10. A correction to F-2, found while measuring

`08-RESEARCH.md` F-2 and this plan's objective say that under l2, `active_regime` *"changes
462 / 587 = 78.7%"*. On that basis they say the state machine *"flickers nearly twice as much as
the raw label"*. **That count treats every NaN → NaN pair as a change**, because
`NaN != NaN` is true.

On the same tracked (pre-filter) `joint_lift_baseline_l2.parquet`, 588 steps from 1972-01-31
to 2020-12-31 with 100 degraded, treating `None`, the neutral posture, as a state gives:
- **122 / 587 changes**;
- **387 / 588** None months, which is correct and unchanged.

So the claim that it flickers twice as much as the label does not hold. 122 is fewer than
state_1's 246. The 387-month all-cash consequence of a hard gate is unaffected.

This number did not decide anything. Glenn's ruling rests on two facts: (b) is the only
mechanism that moves the decision-bearing leg, and (a) implies 387 all-cash months. Both still
hold. The correction is recorded here so the 78.7% is not quoted again. `08-09-SUMMARY.md`
reports l2 change counts both ways, with their definitions.
