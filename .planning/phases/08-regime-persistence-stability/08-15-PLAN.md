<objective>
Fix the neutral-posture display bug that verification human item 4 found in 08-VERIFICATION.md.

**Root cause (diagnosed at planning, from `git show 036ae74` and the real-data page).**
`assemble_weekly_report` §3 starts from the whole `returns_by_regime` table and narrows it with
`returns_by_regime["regime"] == active_regime` only when `active_regime is not None`. Its row
format is `- {asset}: mean=... sharpe=... n_obs=...`, with no regime id. That format was
unambiguous only because the table was always narrowed to one regime.
- Before 08-09 (`036ae74`), `active_regime` was `probs.idxmax()` inside the function, so it was
  never None while a posterior existed. The section always showed one regime.
- 08-09 correctly made the function take the hysteresis OUTPUT instead. That made None (neutral
  posture) reachable. On today's data it is the live case, because no belief component clears the
  0.70 act threshold.
- None falls through to "no narrowing". The page then prints every (regime, asset) row without its
  regime.

Measured on the verifier's real-data page (scratch copy, 2026-09-29 17:52, as-of 2026-06-30): the
section holds **24 rows**, 4 assets × 6 regimes, and each asset appears **six** times. For example,
SPY shows mean −4.22% / Sharpe −2.21 in one row and +2.17% / +1.97 in another, with nothing saying
which regime either belongs to. The verifier wrote "SPY four times"; the page shows six. The
executor re-measures this in Task 1.

**The fix, and why this one (planner's choice, recorded for Glenn's overrule; see the return
message).** The page already states its own rule, directly under the active regime: *"it selects
the trajectory and per-asset rows below and gates no weight"*. The Trajectory section already
honours that rule in neutral posture: it prints "(no trajectory available for the current regime)".
The per-asset section is the one that breaks it. So:
- In neutral posture it prints one sentence and no rows. The sentence says no regime is active, so
  there are no per-asset regime rows, and that the executed book below comes from the filtered
  belief across all regimes.
- Every row that IS printed names its regime id, in the form `- SPY (regime 3): mean=...`, so a
  row can never again be read without its regime.
- The alternative is to print all regimes' rows, grouped and labelled, in neutral posture. That is
  a different reading of the trading page, and it is not implemented. It is listed as an open
  question for Glenn.

**Scope fences.** Only `assemble_weekly_report` §3 changes. It is a pure function. There is no
change to `_build_report_inputs`, the allocation, the belief, the band, or any checkpoint. No
registry row. No holdout read. The CR-01 work (08-16, 08-17) is a separate concern.
</objective>
