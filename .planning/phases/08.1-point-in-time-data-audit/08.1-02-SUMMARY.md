# Phase 8.1 Plan 02: Per-Series STALE Banner and Always-On Allocation Table Summary

The weekly page now judges staleness per series against the run date (7-day grace) and names late series in a STALE DATA banner instead of refusing, and it always prints a class | ticker | target % | last week % | change table, with last week taken from the previously executed book.

## What was built

**Task 1 (tracer), commit 53b943d.**
- Removed `MAX_SCORING_LAG_MONTHS`, its refusal branch in `_scored_row` and the docstring text. The no-complete-month `ValueError` and the "Scored as of" note stay.
- Added `_run_date()` (monkeypatchable), `expected_month_end(run_date, grace_days)` and the pure `stale_series(frame, columns, *, run_date, grace_days) -> dict[str, int | None]`. A series is stale when its last valid value precedes the expected month-end; `None` means never observed. An interior gap is not staleness.
- `_build_report_inputs` watches the non-`derived` `publication_lags` entries present in the full-span `monthly_features`, reads `report.staleness_grace_days` (default 7), and returns `stale_series` and `stale_expected_through`.
- `assemble_weekly_report` prints `## STALE DATA` right after the H1, one line per series (worst first), then one sentence saying the report scores the latest month complete in the model's columns and imputes nothing.

**Task 2, commit cd33426.**
- `_class_by_ticker(cfg)` is the reverse of `cfg["splice"]` in splice order (SPY equities, TLT long_duration, IAU gold, USO oil, FZFXX cash).
- `load_last_executed_weights(cm)` reads the `basis == "executed"` rows (None without a checkpoint, an empty Series for an all-cash book). It is called before `save_executed_weights`, only when a band is configured.
- `_allocation_table` renders "### Target allocation" under the trades heading, before the band sentence and the per-account loop, with or without accounts. The per-account loop and the cash-residual line are unchanged.

**Task 3, commit 8603f24.**
- The README replaces the "refuses past 3 month-ends" sentence with the STALE DATA wording and the always-on table, and adds exactly 3 how-to lines for `config/accounts/<name>.yaml`.
- Recorded test counts in CLAUDE.md (2 sites) and README.md (2 sites) updated 2530 → 2550.

## Deviations from Plan

**1. [Rule 3 - Blocking] `assemble_weekly_report` also takes `stale_expected_through`.**
- The plan's signature is `stale_series=None` alone. The banner's "last value ..., expected through ..." text needs the expected month-end, which `stale_series()`'s `dict[str, int | None]` does not carry. One optional kwarg, `stale_expected_through`, supplies it; without it the lines print only "N months late". `_build_report_inputs` returns it.

**2. [Rule 1 - Bug in an existing test] `test_a_same_month_rerun_serves_the_same_targets` was edited.**
- It compared the whole trades section of run 1 and run 2 for equality. The plan's own design makes the table's last-week column differ between those runs (n/a, then the first run's book), so the comparison went red.
- It now compares the section with the table rows removed, and compares the table's target column across the two runs. The run-to-run reproducibility it guards (same executed book, same trades) is unchanged.
- The plan said the existing account-trade tests would stay unchanged; this one could not.

**3. [Rule 2] Cash row fallback and extras.**
- When the class map has no cash class but `cash` is given (the synthetic serving world's splice has only equities and long_duration), the cash row prints with ticker `CASH`.
- With nothing to show, the block prints "(no target allocation available)".
- A zero change prints `+0.0 pp`, never `-0.0 pp`.
- A one-line caption explains the target and last-week columns.

**4. Extra tests beyond the plan's list.**
- `stale_series` boundaries: never observed, interior gap, month-end run date, no mutation.
- Banner rendering.
- `load_last_executed_weights` against `held_in` rows and the all-cash marker row.
- The real-config class map and order.
- `test_a12_*` asserts `MAX_SCORING_LAG_MONTHS` is gone, placed last so the red evidence is the real behavior.

## Notes for Glenn and the next plan

- **Live page.** The watched list is every non-derived `publication_lags` entry that the full-span `monthly_features` carries. That includes series that may be permanently stale, such as `gold_spot` and `wti_crude` (macrotrends 403-blocks), and ETFs that have ended. They will be named in the banner until the lag table or the watch rule is narrowed. That is honest, but it may be noisy; narrowing is a config or one-line decision for Glenn.
- **Same-month re-run.** On a same-month re-run, "last week" is the book the earlier run of that month already executed, so the change is 0 by design (tested). Across months it is the prior month's executed book.
- **Band off.** With `allocation.no_trade_band` unset, no executed book is persisted, so the last-week column reads n/a.
- Serving-world cfg pins `weekly._run_date` (2021-07-08) with `raising=False`, so every test that runs `weekly.main` on a synthetic world is wall-clock independent.
