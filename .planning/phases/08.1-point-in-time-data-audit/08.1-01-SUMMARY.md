# Phase 8.1 Plan 01: Point-in-Time Lag Table and Test Summary

A measured `publication_lags` table (m2sl 1, totalsl 2, div_yield 3, GDP pre-vintage fallback 3, everything else 0 or derived/vintage) is applied once to the ingest frame in `build_monthly_spine`, and a truncation-by-poisoning test through the real build proves no feature at t moves when values published after t change. The test's own self-test shows it goes red when `div_yield` is lagged 0.

## Deviations from Plan

**1. [Rule 3 - Blocking] Poison factor 1.5 instead of ×1e6.**
- **Found during:** Task 1.
- **Issue:** `splice.assert_yield_units_plausible` raises on any converted yield above 100% annualized, so ×1e6 on `fred_gs10`/`fred_tb3ms` would crash the build instead of testing it.
- **Fix:** `POISON = 1.5`. Any factor other than 1 is caught by the exact rel-1e-9 comparison, and 1.5 keeps every yield plausible. The reason is documented at the constant.
- **Files:** `tests/unit/test_platform_point_in_time.py`.
- **Commit:** 762b9a8.

**2. [Rule 2 - Correctness] Completeness is checked as set equality, not just coverage.**
- Stale extra entries are caught as well as missing ones.
- The test also checks that each entry is the right kind: an int for ingested columns, `derived` for research names, a vintage dict for agency series.

**3. [Rule 2] Extra contract tests beyond the plan's list.**
- `apply_publication_lags`: it shifts timestamps, not positions, across a gap; it never mutates its input; it refuses unlisted, derived and vintage columns.
- `lag_table`: it rejects 9 malformed entry shapes, naming the column.
- `test_bypassing_the_lag_is_detected`: the identity-monkeypatch mutation from RESEARCH §3.
- A marker round-trip test.

**4. The merge-guard check sits before the `daily_raw` save**, not merely before the `monthly_raw` save. This follows the plan's own behavior line: "raises before any write".

**5. The shift-guard test was green at RED time.** `lag_table`'s `shift: true` rejection was written in Task 1, so `TestShiftGuard` passed before Task 2's GREEN commit. The config-level assertion that no `fred_monthly` entry has a `shift` key (in test_platform_macro_ingest.py) was red until Task 2 removed the keys.
