<objective>
Build the L4-04 minimal daily tripwire monitor: three independent-family risk signals combined
by OR-logic into a single escalation enum (none / "run weekly scoring early" / "Tier-1 de-risk
review"), runnable daily by hand via a CLI entry point. TDD (RED→GREEN): the OR-logic truth
table is the headline invariant — 0 triggers → NONE, 1 → early-scoring, 2+ → Tier-1, and it must
be family-count-driven, never signal-identity-driven.

Purpose: The tripwire is the between-weekly-reports safety net (design §23.2, §25) — it tells
Glenn when a fast-moving risk event (vol blow-up, credit stress, price drawdown) warrants acting
before the next scheduled weekly report. v1 is the minimal 3-signal OR subset per D-04; the full
family-independence orchestrator (§25) is v2 (L2-V2-03).

Output: `tripwire/monitor.py` (signals + OR-logic + CLI, in the gap_lag module shape) and a test
file whose OR-logic truth table and per-signal threshold cases are written first.

unit-tested logic is fully synthetic — live data wiring is the same deferred human-verification
item as Phase 1 (FRED_API_KEY / yfinance pending), so this plan does NOT block on real data.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-11 | Tampering | OR-logic tier mapping | high | mitigate | The 8-row truth-table RED test locks the count-driven mapping before merge — a threshold inversion or an identity-based (not count-based) bug fails the test; escalation is a pure, fully-enumerated function |
| T-04-12 | Denial of Service | missing SPY / fred_daily_raw at runtime | medium | mitigate | `run_tripwire` accepts injected series for tests and reads named checkpoints for the live path; a missing checkpoint surfaces a clear KeyError/FileNotFoundError at the daily run (Pitfall 1/2 warning signs), not a silent all-clear — Plan 01 closes both data gaps |
| T-04-13 | Repudiation | tripwire thresholds provenance | low | accept | Thresholds are literature-derived config defaults (A3), not tuned on holdout data — no registry logging required in v1; Phase 5's honest backtest is the real validation |
| T-04-SC | Tampering | pip/npm/cargo installs | low | accept | No new dependencies — no install step, no supply-chain surface |
</threat_model>
