# Pipeline Monitoring & Notebook Expansion Plan

**Created:** 2026-03-23
**Status:** Planning — awaiting owner approval on phase ordering

This document breaks a large expansion request into small, independently-executable
work items. Each item is scoped to fit within a single Claude Code session without
timeout issues.

---

## Goals

1. **More monitoring** — each pipeline step should validate its outputs before the next step runs
2. **More plots** — new visualization functions in `plotting.py` for model evaluation
3. **Richer notebooks** — each notebook becomes a comprehensive diagnostic workbench
4. **Plot reuse** — notebooks load pre-generated PNGs from `outputs/plots/` when available
5. **Email attachments** — key plots embedded in the weekly email
6. **Tweaking support** — notebooks become the primary tool for exploring "what if" changes

---

Claude Code session without timeout. Larger items (D3, D5, D8) may need to be
split into sub-items at execution time.

## What This Enables

After all phases complete, the workflow becomes:

1. `python run_pipeline.py --refresh --plots` → runs full pipeline with validation
   gates at every step, generates 30+ diagnostic plots to `outputs/plots/`
2. `jupyter lab notebooks/` → notebooks instantly display pre-generated plots,
   with option to regenerate interactively for parameter exploration
3. `python run_pipeline.py --weekly-report --send-email` → weekly email includes
   key plots as inline images
4. Any notebook can be used for "what if" exploration: change a config parameter,
   re-run a cell, see the impact immediately via comparison plots
